From slopes to a data structure

Why the next step is an object that remembers how it was made

In the lecturePart 1 ended with c: bump it, and d rises by exactly the bump, so the slope is 1. With that intuition for what a derivative tells you, the lecture moves to neural networks. Those are going to be pretty massive mathematical expressions, so we need data structures that maintain these expressions. That is what gets built now: the value object from micrograd’s README.

This is the turn the whole series hinges on. Nudging works, but it costs one extra pass through the expression for every input (part 1, move 10). To get every derivative at once, the program has to remember how each number was made — which numbers went in, and which operation combined them. A plain Python float forgets all of that the moment it’s computed. A Value won’t.

Elsewhere in these notesThe README example, with its forward pass of 24.7041 and a.grad of 138.8338, is part 1, move 2. This page builds the class that makes it work.

2

Teaching Python to add

Value: a wrapper with __repr__, __add__ and __mul__

In the lectureThe skeleton is tiny: class Value takes a single scalar that it wraps and keeps track of. Value(2.0) prints as Value(data=2.0) because of __repr__; without it you’d get something cryptic. Adding two values fails at first — Python doesn’t know how — so you tell it, using the special double-underscore methods. When you write a + b, Python internally calls a.__add__(b): self is a, other is b. It returns a new Value wrapping the sum of the two .data fields — and since data is an ordinary Python number, that + is just floating-point addition. a + b gives Value(data=-1.0). Multiplication is the same with __mul__, and a*b + c, which Python runs as a.__mul__(b).__add__(c), gives Value(data=4.0) — the d from part 1. You can call the methods by hand too.

class Value:
    def __init__(self, data):
        self.data = data

    def __repr__(self):
        return f"Value(data={self.data})"

    def __add__(self, other):
        return Value(self.data + other.data)

    def __mul__(self, other):
        return Value(self.data * other.data)


a = Value(2.0)
b = Value(-3.0)
c = Value(10.0)
print(a + b)            # Python calls a.__add__(b)
print(a * b + c)        # (a.__mul__(b)).__add__(c)
print(a.__mul__(b).__add__(c))
Value(data=-1.0)
Value(data=4.0)
Value(data=4.0)

The class as it stands at this point in the lecture, simplified from the notebook in nn-zero-to-hero by Andrej Karpathy (MIT licence). It’s also Build it, exercise 1.

Two things to notice. Each operation makes a new object, so a, b and c are never changed by being used. And the arithmetic itself is still Python’s: the class only wraps it. Everything interesting in micrograd is about what else a Value records on the side.

Beyond the lectureThis is Python’s data model at work. The documentation spells out the rule the lecture relies on: “to evaluate the expression x + y, where x is an instance of a class that has an __add__() method, type(x).__add__(x, y) is called”, and __repr__ computes the “official” string representation, which should ideally look like an expression that recreates the object — hence Value(data=4.0) (Python data model). One consequence shows up soon: 2 * a fails, because Python first asks the float 2 to multiply by a Value. The fix is a “reflected” method, __rmul__, which micrograd adds later.

3

Children and an operation

_prev and _op: every value remembers where it came from

In the lectureWhat’s missing is the connective tissue of the expression: pointers saying which values produced which. A new constructor argument, _children, defaults to an empty tuple, but the class stores it as _prev, a set — the original micrograd did it that way, Karpathy recalls, probably for efficiency. Values made with the constructor have no children; values made by + or × get (self, other). Now d._prev shows the two values d came from, Value(-6.0) and Value(10.0). The last missing piece is which operation created a value: _op, an empty string for leaves, '+' or '*' otherwise. d._op is '+'. Now we have the full mathematical expression: for every value, how it came to be, by what operation, from what other values.

class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self._prev = set(_children)
        self._op = _op

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), '+')

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), '*')

From the lecture notebook (MIT licence), cut down to this stage.

Notice what kind of structure this is. Each value points only backwards, to its inputs; nothing points forwards. That’s all a backward pass needs: start from the output and follow the pointers home. A value with no children is a leaf — an input you set, like a, b, c or, in a network, a weight.

Watch forA set has no order and keeps each element once. So printing _prev can list the children either way round, and a + a records a only once among its children. Neither matters yet; part 3 comes back to values that are used twice.

Drawing the graph

draw_dot, labels, and the forward pass to L = −8

In the lectureExpressions are about to grow, so Karpathy pastes in some “slightly scary” code: draw_dot, which draws the graph under any root value using Graphviz, open-source graph-visualisation software. A helper, trace, walks back from the root and collects every node and edge. Each value becomes a box; for each value with an _op, the code adds a fake operation node just for display, so a ‘+’ circle sits between c, e and d. Only the boxes are real Value objects. Labels make it readable: label='' by default, then a, b and c are labelled, e = a×b (“kind of naughty”) and d = e + c. One layer deeper: f = Value(−2.0) and L = d × f, which is −8. That is the forward pass: several inputs, a, b, c and f, going into a mathematical expression that produces a single output, L.

Without Graphviz installed, a few lines of plain Python print the same graph as a tree — the output on top, each value’s inputs indented beneath it:

class Value:
    def __init__(self, data, _children=(), _op='', label=''):
        self.data = data
        self.grad = 0.0
        self._prev = set(_children)
        self._op = _op
        self.label = label

    def __repr__(self):
        return f"Value(data={self.data})"

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), '+')

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), '*')


def show(v, indent=0):
    """Print the graph as a tree, output first: a text stand-in for draw_dot."""
    op = f"  ({v._op})" if v._op else ""
    print(" " * indent + f"{v.label} = {v.data}  grad {v.grad}{op}")
    for child in sorted(v._prev, key=lambda c: c.label):   # sorted: a set has no order
        show(child, indent + 4)

5

A grad for every value

What backpropagation fills in, and why it starts at zero

In the lectureNext comes backpropagation: start at the end, go backwards, and compute the gradient along all the intermediate values — for every value, the derivative of L with respect to it. The derivative of L with respect to L is 1; then dL/df, dL/dd, dL/dc, dL/de, dL/db and dL/da. In a neural network, L would be the loss, and some of the leaves would be the network’s weights, others the data. You want the loss’s derivatives with respect to the weights, because those get iterated on with the gradient; the data is fixed, so its derivatives usually aren’t used. So each value gets a new attribute, grad, initialised to 0 — and zero means no effect: at first we assume that changing a value doesn’t change the output. draw_dot now shows each box’s data and grad.

Read grad as an answer waiting to be filled in: if I nudged this value, how would L move? It’s the same question part 1 answered by nudging, asked of every node in the graph at once. And it’s always about the final output: e.grad isn’t a property of e, it’s a fact about e’s place in this particular expression.

Lecture ↔ bookIn the book’s language, L is the loss L[φ] and the weights are the parameters φ. Chapter 7 states the goal the same way: the derivatives ∂ℓi/∂βk and ∂ℓi/∂Ωk for every bias and weight (move 11).

The base case

dL/dL = 1, and a staging area for checking

In the lectureStart all the way at the end. What is the derivative of L with respect to L? Change L by a tiny amount h, and L changes by h: proportional, so the derivative is 1. The numbers can be checked numerically, as in part 1. Karpathy wraps the expression in a function, lol(), as a staging area, so that its variables stay local and don’t pollute the notebook’s global scope. Inside, build the expression once and keep L1 = L.data; build it again with one value bumped by h and keep L2; print (L2 − L1)/h — rise over run, using .data because L is a Value. Bumping a gives 6; bumping L itself, awkwardly, gives 1: the base case. So set L.grad = 1 by hand and redraw.

Every backward pass starts this way, whatever the graph. The seed is 1 because the question at the top is trivial — how does L move when L moves? — and every other answer will be built from it by multiplication.

Beyond the lectureChecking backprop against nudging is called a gradient check, and it is how real implementations are debugged. Stanford’s CS231n notes recommend the centred difference, (f(x + h) − f(x − h)) / 2h, whose error shrinks like h² rather than h, and comparing the two gradients by relative error rather than their raw difference (CS231n, “Gradient checks”). Part 1 met the centred difference in Build it, exercise 1.

7

Through a times node

dL/dd = f and dL/df = d

In the lectureNext, d and f. L is d × f, so what is dL/dd? If you know your calculus, it’s f. If you don’t believe it, go back to the definition: bump d by h and you get (d + h)·f; subtract d·f and divide by h. Expanding, d·f + h·f − d·f over h: the d·f terms cancel, leaving h·f over h, which is f. By symmetry, dL/df = d. So f.grad = d = 4 and d.grad = f = −2. Checked in the staging area: bumping f prints 4, “up to floating-point funkiness”, and bumping d prints −2. That’s an inline gradient check: deriving the backward pass, then confirming each derivative with a small numerical step.

L = d · f  ⟹  ∂L/∂d = f = −2,   ∂L/∂f = d = 4a times node: each input’s slope is the other input

That “other input” is worth saying out loud, because it is the whole rule for multiplication. Making d a little bigger changes L by f times as much, and making f a little bigger changes L by d times as much. A times node hands each of its inputs the value of the other one.

8

The chain rule

The crux: how c reaches L through d

In the lectureThis is the most important node to understand: get its gradient and you understand all of backpropagation, and basically all of training. We want dL/dc. We know dL/dd = −2: how L responds to d. If we also know how c affects d, we should be able to combine them. That second piece is a local derivative. d = c + e, so dd/dc is 1: from the definition, (c + h + e) − (c + e) over h leaves h/h, which is 1; and by symmetry dd/de = 1. It’s “local” because the little ‘+’ node knows nothing about the rest of the graph it sits in. It only knows that it added c and e to make d, and how each of them moves d. To combine local derivatives you need the chain rule. Calculus classes can make it confusing; the version Karpathy likes, from Wikipedia: if z depends on y, and y depends on x, then dz/dx = dz/dy · dy/dx — chained derivatives multiply. Wikipedia’s intuition: if a car travels twice as fast as a bicycle, and the bicycle four times as fast as a walking man, the car travels 2 × 4 = 8 times as fast as the man. Here z is L, y is d and x is c: dL/dc = dL/dd · dd/dc = −2 × 1 = −2, and the same for e. Because a plus node’s local derivatives are 1, a plus node just routes the gradient, distributing it unchanged to all its children. Bump c, then e, in the staging area: −2 and −2.

dL/dc = dL/dd · dd/dc = (−2) · 1 = −2upstream gradient × local derivative — the chain rule, one node at a time
Try it — rates multiply

The car, the bicycle and the walker. Set how much faster the car is than the bicycle, and the bicycle than the walker; the chain rule says the car’s speed relative to the walker is the product.

8×car ÷ walker, dz/dx

Beyond the lectureThe car-and-bicycle line comes from George F. Simmons’s calculus textbook, quoted in Wikipedia’s article on the chain rule. Leibniz’s notation makes the rule look like cancelling fractions — the dy “cancels” in dz/dy · dy/dx — which is a handy memory aid, though not a proof.

9

All the way to the leaves

Times again: a.grad = 6 and b.grad = −4

In the lectureOne more application of the chain rule finishes the graph. We know dL/de = −2. e = a × b, and a little ‘×’ node knows only its local derivatives: de/da = b = −3 and de/db = a = 2. So a.grad = dL/de × de/da = −2 × −3 = 6, and b.grad = −2 × 2 = −4. Checked by nudging: 6, and −4 “plus or minus floating-point oddness”. That is the manual backpropagation, from L all the way to the leaves. All we did was iterate through the nodes one by one and apply the chain rule locally. We always know the derivative of L with respect to a node’s output; we look at the operation that produced it, which has pointers to its children; we know that operation’s local derivatives; and we multiply them onto the derivative we already have. That is backpropagation: a recursive application of the chain rule, backwards through the computation graph.

+

A plus node routes

Each input’s grad is the output’s grad, unchanged: the local derivative is 1.

×

A times node swaps

Each input’s grad is the other input’s value times the output’s grad.

Try it — backpropagate the graph by hand

The lecture’s graph, drawn top-down: inputs at the top, L at the bottom. Press “Backward one step” to fill in the grads from L upwards, with each step’s upstream × local shown below. Then check the leaves by nudging, or take one step uphill. Change the inputs and start again.

Two rules were enough for the whole graph, and that’s no accident: plus and times are the only operations in it. Every new operation — tanh, exp, a power — brings exactly one new local derivative, and nothing else about the procedure changes. Part 3 adds the first one.

One step uphill

Nudging the inputs to raise L — and what comes next

In the lectureTo see the power of this: nudge the inputs to make L go up. The leaves are what we usually control, so move each of a, b, c and f in the direction of its gradient by a small step size, 0.01. A positive nudge along the gradient should have a positive influence on L, so −8 should become less negative. Rerun the forward pass and print L.data: −7.29, about −7. This is one step of the optimisation that will end up running in training. The gradient gives us power, because we know how to influence the final outcome. Next, the lecture does one more manual backpropagation on a more complex and useful example — a neuron, in part 3.

a, b, c, f = 2.0, -3.0, 10.0, -2.0
grads = {'a': 6.0, 'b': -4.0, 'c': -2.0, 'f': 4.0}   # from exercise 4

def forward(a, b, c, f):
    return (a * b + c) * f

print("before:", forward(a, b, c, f))
step = 0.01
a += step * grads['a']
b += step * grads['b']
c += step * grads['c']
f += step * grads['f']
print("after one step uphill:", forward(a, b, c, f))
before: -8.0
after one step uphill: -7.286496

Following the lecture notebook’s cell (MIT licence), which prints −7.286496.

Beyond the lectureTraining does the same thing in the other direction. A loss should go down, so each weight steps against its gradient: w ← w − α·∂L/∂w, gradient descent, with α the learning rate (part 1, move 15, walks a line downhill this way). Stepping uphill here just demonstrates that the gradient really points the way L climbs. Keep the step small: a gradient describes the slope where you are, and a big step lands somewhere it no longer describes.

Why gradients are the bottleneck

Chapter 7 and section 7.1: a derivative for every parameter, at every step

Chapter 6 of Understanding Deep Learning introduced iterative optimisation: choose initial parameters at random, then make a series of small changes that lower the loss, each based on the gradient of the loss at the current position. Chapter 7 deals with two problems specific to neural networks. The first is computing the gradients efficiently — a real challenge when the largest models had around 1012 parameters at the time of writing, and the gradient is needed for every one of them at every iteration. The second, initialisation, belongs to a later page.

Section 7.1 sets up the problem with a network of three hidden layers, each a[βk + Ωkhk] as in chapter 4, and a loss made of one term per training example, ℓi — for instance the least-squares (f[xi, φ] − yi)2 — added up into L[φ]. The usual training algorithm, stochastic gradient descent, updates the parameters with

φt+1 ← φt − α · Σi ∈ Bt ∂ℓi/∂φα the learning rate · Bt the examples in this step’s batch

So training needs ∂ℓi/∂βk and ∂ℓi/∂Ωk for every layer k and every example in the batch. The backpropagation algorithm computes them efficiently.

Lecture ↔ bookThose are exactly the .grads of move 5, for weight and bias leaves; micrograd will compute them one scalar at a time, where the book uses vectors and matrices (part 1, move 23). The update rule is move 10’s step, pointed downhill and summed over a batch.

12

Two observations

Section 7.2: store the activations, then reuse the work

Before any formulas, section 7.2 makes two observations that explain why backpropagation is shaped the way it is.

  • Observation 1. Each weight multiplies the activation at its source hidden unit and adds the result to a destination unit in the next layer. So the effect of a small change to the weight is scaled by that source activation: if the activation doubles, so does the weight’s effect. Hence you run the network forward and store every hidden activation — the forward pass — because the gradients will need them.
  • Observation 2. A small change to a bias or weight ripples through every later layer, then the output, then the loss. To know how a parameter moves the loss, you need to know how each later layer moves the one after it — and those same quantities are needed for the other parameters in the same or earlier layers. So compute them once and reuse them, starting at the end and working back: the backward pass.

Working backwards, most of the terms you need have already been computed one step earlier. The full derivation needs matrix calculus, so the book first works through a model with scalar parameters.

Lecture ↔ bookObservation 1 is the times node of move 7: a.grad is b × e.grad, so a’s effect is scaled by the value it multiplied. Observation 2 is the chain rule’s bookkeeping in move 8: d.grad was computed once and then reused for both c and e.

A toy model with sin, exp and cos

Section 7.3: eight scalar parameters, and the forward pass, stored

The toy model has one input, one output and eight scalar parameters, built from three functions:

f[x, φ] = β3 + ω3 · cos[β2 + ω2 · exp[β1 + ω1 · sin[β0 + ω0 · x]]]with the least-squares loss ℓi = (f[xi, φ] − yi)2

Think of it as a network with one hidden unit per layer, and a different activation function — sin, exp, cos — in each. The goal is the eight derivatives ∂ℓi/∂βk and ∂ℓi/∂ωk. You could derive each by hand, but the expressions get ugly: the book’s formula for ∂ℓi/∂ω0 runs to three lines and contains the same exponential three times. Hard to derive, easy to code wrongly, and wasteful.

Backpropagation instead starts with a forward pass that treats the loss as a series of small calculations, and stores every intermediate value:

f0 = β0 + ω0·x  ·  h1 = sin[f0]
f1 = β1 + ω1·h1  ·  h2 = exp[f1]
f2 = β2 + ω2·h2  ·  h3 = cos[f2]
f3 = β3 + ω3·h3  ·  ℓi = (f3 − yi)2

Lecture ↔ bookThat list is an expression graph like the lecture’s, written as lines of code: plus and times nodes, with three new kinds of node, sin, exp and cos. In micrograd, each line would create one Value and remember its children.

14

Backward, twice

Section 7.3: the intermediate values first, then the parameters

Backward pass #1 computes the derivatives of the loss with respect to the stored intermediate values, in reverse order. The first is direct: ∂ℓi/∂f3 = 2(f3 − yi). The next uses the chain rule: ∂ℓi/∂h3 = ∂f3/∂h3 · ∂ℓi/∂f3, where ∂f3/∂h3 is simply ω3. Each further step multiplies the previous result by one simple factor — the derivative of cos, exp or sin at the stored value, or another ω — so everything already computed is reused rather than recomputed.

Backward pass #2 turns those into the parameters’ derivatives, by the chain rule once more:

∂ℓ/∂βk = 1 · ∂ℓ/∂fk    ∂ℓ/∂ωk = hk · ∂ℓ/∂fkbecause fk = βk + ωk·hk; for k = 0 the source is the input, so ∂ℓ/∂ω0 = xi · ∂ℓ/∂f0

That matches observation 1: a weight’s effect is proportional to its source value, hk, which the forward pass stored. Backpropagation is both simpler and more efficient than deriving each parameter’s formula separately. The book’s companion is notebook 7.1, Backpropagation in toy model.

Exercise 2 · moves 3–5

Remember the graph

Add _children (stored as the set _prev), _op, label and grad = 0.0. Build L = (a·b + c)·f with the lecture’s labels, then write show(v), which prints a value and, indented beneath it, its children — a text version of draw_dot.

One way to write it 
class Value:
    def __init__(self, data, _children=(), _op='', label=''):
        self.data = data
        self.grad = 0.0
        self._prev = set(_children)
        self._op = _op
        self.label = label

    def __repr__(self):
        return f"Value(data={self.data})"

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), '+')

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), '*')


def show(v, indent=0):
    """Print the graph as a tree, output first: a text stand-in for draw_dot."""
    op = f"  ({v._op})" if v._op else ""
    print(" " * indent + f"{v.label} = {v.data}  grad {v.grad}{op}")
    for child in sorted(v._prev, key=lambda c: c.label):   # sorted: a set has no order
        show(child, indent + 4)


a = Value(2.0, label='a')
b = Value(-3.0, label='b')
c = Value(10.0, label='c')
e = a * b; e.label = 'e'
d = e + c; d.label = 'd'
f = Value(-2.0, label='f')
L = d * f; L.label = 'L'
print(L, L._op)
show(L)
Value(data=-8.0) *
L = -8.0  grad 0.0  (*)
    d = 4.0  grad 0.0  (+)
        c = 10.0  grad 0.0
        e = -6.0  grad 0.0  (*)
            a = 2.0  grad 0.0
            b = -3.0  grad 0.0
    f = -2.0  grad 0.0

The children are sorted by label before printing because a set has no order; without that, c and e could swap places from run to run.

Exercise 3 · moves 6–9

The staging area

Write L_of(a, b, c, f) and estimate dL/da, dL/db, dL/dc and dL/df by bumping each input by h = 0.001 — the lecture’s lol(), as a function of plain floats. Then bump the internal nodes d and e directly.

One way to write it 
def L_of(a, b, c, f):
    e = a * b
    d = e + c
    return d * f

h = 0.001
base = L_of(2.0, -3.0, 10.0, -2.0)
print("L =", base)
for name, args in [("a", (2.0 + h, -3.0, 10.0, -2.0)),
                   ("b", (2.0, -3.0 + h, 10.0, -2.0)),
                   ("c", (2.0, -3.0, 10.0 + h, -2.0)),
                   ("f", (2.0, -3.0, 10.0, -2.0 + h))]:
    print(f"dL/d{name} ~ {(L_of(*args) - base) / h:.6f}")

# the internal nodes: bump d or e directly (L = d*f, d = e + c)
d, e, f = 4.0, -6.0, -2.0
print(f"dL/dd ~ {((d + h) * f - d * f) / h:.6f}")
print(f"dL/de ~ {(((e + h) + 10.0) * f - (e + 10.0) * f) / h:.6f}")

Exercise 4 · moves 6–9

Backpropagate by hand

Starting from the forward values, fill in every gradient in reverse order, writing each one as local derivative × upstream gradient. Compare with exercise 3.

One way to write it 
# values from the forward pass
a, b, c, f = 2.0, -3.0, 10.0, -2.0
e = a * b          # -6.0
d = e + c          #  4.0
L = d * f          # -8.0

# the backward pass, by hand: upstream grad times local derivative
grad = {}
grad['L'] = 1.0                        # base case: dL/dL
grad['d'] = f * grad['L']              # times node: the local derivative is the OTHER input
grad['f'] = d * grad['L']
grad['e'] = 1.0 * grad['d']            # plus node: local derivative 1, it just routes
grad['c'] = 1.0 * grad['d']
grad['a'] = b * grad['e']              # times node again
grad['b'] = a * grad['e']

for k in "Ldfeca" + "b":
    print(f"d L / d {k} = {grad[k]}")
d L / d L = 1.0
d L / d d = -2.0
d L / d f = 4.0
d L / d e = -2.0
d L / d c = -2.0
d L / d a = 6.0
d L / d b = -4.0

Every line has the same shape. Part 3 moves each of these lines into the operation that created the node, so the class can run them itself.

Exercise 5 · move 10

One step uphill

Using the gradients from exercise 4, nudge each leaf by 0.01 × its gradient and run the forward pass again. Does L go up? Then try stepping against the gradients instead.

One way to write it 
a, b, c, f = 2.0, -3.0, 10.0, -2.0
grads = {'a': 6.0, 'b': -4.0, 'c': -2.0, 'f': 4.0}   # from exercise 4

def forward(a, b, c, f):
    return (a * b + c) * f

print("before:", forward(a, b, c, f))
step = 0.01
a += step * grads['a']
b += step * grads['b']
c += step * grads['c']
f += step * grads['f']
print("after one step uphill:", forward(a, b, c, f))
before: -8.0
after one step uphill: -7.286496

Against the gradients, L falls to −8.7, which is what training will do to a loss. Repeat the step a few times and recompute the gradients each time: they change as you move, because a gradient belongs to a point.

Exercise 6 · stretch · moves 13–14

The book’s toy model

Code the sin–exp–cos model of section 7.3 with any eight parameters. Run the forward pass, storing every fk and hk; run backward pass #1 and #2 by hand; and check ∂ℓ/∂ω0 by nudging.

One way to write it 
import math

# UDL section 7.3: f[x] = b3 + w3*cos(b2 + w2*exp(b1 + w1*sin(b0 + w0*x))), loss (f - y)^2
b0, w0, b1, w1, b2, w2, b3, w3 = 0.3, 1.2, -0.4, 0.9, 0.5, -0.7, 0.2, 1.1
x, y = 0.8, 1.0

def forward(b0, w0, b1, w1, b2, w2, b3, w3):
    f0 = b0 + w0 * x;  h1 = math.sin(f0)
    f1 = b1 + w1 * h1; h2 = math.exp(f1)
    f2 = b2 + w2 * h2; h3 = math.cos(f2)
    f3 = b3 + w3 * h3
    return f0, h1, f1, h2, f2, h3, f3, (f3 - y) ** 2

f0, h1, f1, h2, f2, h3, f3, loss = forward(b0, w0, b1, w1, b2, w2, b3, w3)
print(f"forward: f3 = {f3:.6f}, loss = {loss:.6f}")

# backward pass #1: derivatives with respect to the intermediate values, end first
dl_df3 = 2 * (f3 - y)
dl_dh3 = w3 * dl_df3
dl_df2 = -math.sin(f2) * dl_dh3
dl_dh2 = w2 * dl_df2
dl_df1 = math.exp(f1) * dl_dh2
dl_dh1 = w1 * dl_df1
dl_df0 = math.cos(f0) * dl_dh1

# backward pass #2: the parameters. d f_k / d b_k = 1, d f_k / d w_k = h_k (x for k = 0)
print(f"dl/dw0 by backprop: {x * dl_df0:.6f}")

# check one of them numerically
h = 1e-6
bumped = forward(b0, w0 + h, b1, w1, b2, w2, b3, w3)[-1]
print(f"dl/dw0 by nudging:  {(bumped - loss) / h:.6f}")

dl/dw0 by backprop: -0.031845
dl/dw0 by nudging:  -0.031845

Check yourself

Sixteen questions: tap an answer to see the reason. Your first tap on each question is the one that counts.

1. You write a + b with two Values. What does Python run?

The left operand’s __add__ is called, with the right one as other (move 2).

2. What is __repr__ for?

It returns the “official” string representation that Python shows when you print or inspect the object.

3. What does _prev hold?

Its children, stored as a set: for d = e + c, that’s e and c (move 3).

4. In draw_dot, what are the little ‘+’ and ‘×’ circles?

The drawing invents an op node for each value that has an _op, so the picture reads nicely (move 4).

5. After backpropagation, what is c.grad?

Every grad is about the final output: how L moves when that value is nudged (move 5).

6. Why does every grad start at 0?

Until the backward pass fills it in, a value is assumed not to affect the output (move 5).

7. L = d · f with d = 4 and f = −2. What is dL/dd?

For a product, each input’s derivative is the other input: f, which is −2 (move 7).

8. A plus node’s local derivative with respect to each input is…

(c + h + e) − (c + e) over h is 1: a plus node routes the gradient to all its children (move 8).

9. A car is twice as fast as a bicycle, which is four times as fast as a walker. The car is how many times as fast as the walker?

Rates of change multiply, 2 × 4: the chain rule (move 8).

10. e = a · b with b = −3, and e.grad = −2. What is a.grad?

Upstream × local: −2 × b = −2 × −3 = 6 (move 9).

11. Backpropagation is…

Start from L.grad = 1 and, node by node, multiply on each operation’s local derivatives (move 9).

12. To make L go up, how should each leaf move?

leaf += 0.01 × grad: L went from −8 to −7.29 (move 10).

13. In training, to lower a loss, each weight steps…

w ← w − α·∂L/∂w: gradient descent, the same step pointed downhill.

14. Which derivatives does training actually use?

The weights are what gets updated; the data is fixed (move 5).

15. Why does the book’s forward pass store every hidden activation?

Observation 1 (move 12): ∂ℓ/∂ωk = hk · ∂ℓ/∂fk needs the stored hk.

16. With fk = βk + ωk·hk, what is ∂fk/∂ωk?

The times node again: a weight’s local derivative is the value it multiplies (move 14). The bias gets 1.

A backward step for every operation

_backward: each node’s own little piece of the chain rule

In the lectureTime to codify the hand calculations. Each Value gets a special _backward: a function that does the little piece of chain rule at each node that took inputs and produced an output — how to chain the output’s gradient into the inputs’ gradients. By default it is a function that does nothing, which is right for a leaf. When __add__ creates out, it also defines out’s backward step, stored in a closure: take out.grad and propagate it into self.grad and other.grad, each the local derivative times the “global” derivative — the derivative of the final output with respect to out. For addition the local derivative is 1.0, so out.grad is simply copied onto both. For multiplication, self.grad = other.data * out.grad and other.grad = self.data * out.grad. For tanh, self.grad = (1 - t**2) * out.grad, where t is tanh’s own output.

def __add__(self, other):
    out = Value(self.data + other.data, (self, other), '+')
    def _backward():
        self.grad = 1.0 * out.grad
        other.grad = 1.0 * out.grad
    out._backward = _backward
    return out

def __mul__(self, other):
    out = Value(self.data * other.data, (self, other), '*')
    def _backward():
        self.grad = other.data * out.grad
        other.grad = self.data * out.grad
    out._backward = _backward
    return out

The lecture’s code at this stage, following the notebook in nn-zero-to-hero by Andrej Karpathy (MIT licence). The = signs are deliberate; move 5 changes them.

The closure is what makes this work. The inner function _backward refers to self, other and out, and Python keeps those references alive inside it. Long after __add__ has returned, out._backward still knows exactly which two values to update and where the gradient comes from. Each node carries its own backward step with it.

Calling them by hand

A funny slip, then the neuron’s backward pass, one call at a time

In the lectureRedefine the neuron with all grads at 0, and instead of filling in gradients by hand, call each _backward in the right order. One catch: every backward step multiplies by out.grad, which starts at 0, so first set the base case, o.grad = 1.0. The first attempt fails with a “’NoneType’ object is not callable” error, left in because “it’s pretty funny”: the code said out._backward = _backward(), which calls the function — and these functions return None. The fix is to store the function, not call it. Then o._backward() gives n its 0.5; n._backward() routes 0.5 to both its inputs; b._backward() does nothing, because b is a leaf whose backward is the empty function — harmless to call; then the sum, then the two products. Out come the same gradients as before — w2 0, x2 0.5, x1 −1.5, w1 1 — but computed by the nodes themselves.

o.grad = 1.0
o._backward()          # n.grad = 0.5
n._backward()          # routes 0.5 to the sum and to b
b._backward()          # a leaf: nothing happens
x1w1x2w2._backward()   # routes 0.5 to both products
x2w2._backward()       # x2.grad = 0.5, w2.grad = 0
x1w1._backward()       # x1.grad = -1.5, w1.grad = 1

Watch forThe slip is worth remembering, because it is easy to make: f is a function, f() is whatever the function returns. A backward step must be stored to run later; calling it while building the graph runs it too early, with out.grad still 0, and leaves None behind.

3

Topological sort

Never call a node’s backward before everything after it

In the lectureOne manual piece remains: deciding the order. Going backwards through an expression means we never call a node’s _backward before we’ve done everything after it — everything that depends on it has to propagate its gradient to it first. That ordering is a topological sort: a layout of a directed acyclic graph (DAG) such that all the edges go one way, left to right; one graph can have several. The implementation keeps a set of visited nodes and starts at the root, o. If a node hasn’t been visited, mark it, go through all of its children, and only after all the children have been processed, add the node itself to the list. That is the invariant: a node is in the list only once all its children are. Built from o, the list ends with n and then o, the 0.7071 output, with everything else laid out before them.

topo = []
visited = set()
def build_topo(v):
    if v not in visited:
        visited.add(v)
        for child in v._prev:
            build_topo(child)
        topo.append(v)
build_topo(o)

The list topo

Beyond the lectureThis is the depth-first version of topological sorting; the other classic is Kahn’s algorithm, which repeatedly removes nodes that nothing else points to (Wikipedia). The recursive version has one practical limit in Python: each level of the graph is a nested call, and CPython stops at a recursion depth of about a thousand. Fine for micrograd’s graphs; a very long chain would need an iterative version with its own stack.

4

backward()

Hide the bookkeeping inside the Value class

In the lectureReset the grads, and the whole procedure is three steps: set o.grad = 1, the base case; build the topological order; then for each node in reversed(topo), call node._backward(), starting at o. The derivatives come out right. Finally, hide it in the class, “because we don’t want to have all that code lying around”: a real backward, without the underscore, which builds the topological order from self, sets self.grad = 1 and runs every backward step in reverse. Now a single o.backward() does it all: backpropagation through the whole neuron, with no manual steps.

def backward(self):
    topo = []
    visited = set()
    def build_topo(v):
        if v not in visited:
            visited.add(v)
            for child in v._prev:
                build_topo(child)
            topo.append(v)
    build_topo(self)

    self.grad = 1.0
    for node in reversed(topo):
        node._backward()

From the lecture notebook (MIT licence).

Lecture ↔ bookThe book makes the same point about real frameworks: in its PyTorch example, “all of the details of the backpropagation are hidden in the single line of code: loss.backward()” (move 13). This is that line, and you now know what’s behind it.

5

The += bug

A value used twice must collect both contributions

In the lecture“We shouldn’t be too happy with ourselves”: there’s a bad bug, hidden so far by the particular expressions used. The simplest case: a = 3, b = a + a, then b.backward(). The forward pass is fine — b is 6 — but a.grad comes out 1, when calculus says it should be 2, 1 + 1. In __add__’s backward step, self and other are the same object, so a.grad is set to 1, then set to 1 again: overwritten. A second example: a and b, d = a × b, e = a + b, f = d × e; f.backward() gives wrong gradients. The problem appears any time a variable is used more than once: e’s backward step deposits gradients into a and b, then d’s overwrites them. The fix comes from the multivariate case of the chain rule: the gradients add, so instead of setting them, accumulate them with +=. That’s safe because every grad starts at 0. Now a + a gives 2, and in the second example each branch’s contribution simply adds on top of the other’s.

∂f/∂a = ∂f/∂d · ∂d/∂a + ∂f/∂e · ∂e/∂a = e·b + d·1 = 1·3 + (−6) = −3a reaches f along two paths; the chain rule sums the paths
Try it — = against +=

Pick an expression and a rule for depositing gradients. The log shows every deposit the backward pass makes, in order; underneath, each leaf’s gradient is checked against nudging.

    Beyond the lecturePyTorch accumulates in exactly the same way. Its documentation says a tensor’s .grad starts as None, and after the first backward pass “future calls to backward() will accumulate (add) gradients into it” (torch.Tensor.grad). That is why training code resets the gradients before each backward pass, which part 5 will need too. micrograd’s finished engine.py uses += in every backward step.

    Numbers that aren’t Values

    Wrapping constants, and __rmul__

    In the lectureAfter tidying up, the lecture returns to tanh, to break it into its pieces — to prove you get the same results and gradients, and because it forces more operations: exponentiation, addition, subtraction, division. First, a + 1 fails: “int object has no attribute data”, because 1 isn’t a Value. As a convenience, leave other alone if it’s a Value, and otherwise wrap it in one; the same in __mul__. Now a * 2 works — but 2 * a doesn’t. Python runs that as 2.__mul__(a), and an int can’t multiply a Value. Python’s fallback is __rmul__: if 2 * a fails, it checks whether a knows how to be multiplied by 2, and calls a.__rmul__(2), which simply swaps the operands and returns a * 2. Now 2 * a gives 4.

    def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    ...

def __rmul__(self, other):   # other * self
    return self * other

    Beyond the lecturePython calls these the reflected operators: __radd__, __rmul__ and the rest are “only called if the operands are of different types, when the left operand does not support the corresponding operation” (Python data model). micrograd’s finished engine adds __radd__, __rsub__ and __rtruediv__ too, so 1 - a and 1 / a work as well.

    exp, powers, division, subtraction

    Each new operation brings one new local derivative

    In the lectureexp mirrors tanh: one scalar in, one out. Its backward step needs the local derivative of ex, which is “famously just ex” — already computed and sitting in out.data, so self.grad += out.data * out.grad. For division, Karpathy implements something more general: a/b is a·(1/b), which is a · b−1, so implement xk for a constant k, an int or a float, and division becomes a special case. __pow__’s forward pass is self.data**other; its backward step uses the power rule, d/dx xn = n·xn−1: self.grad += other * self.data**(other - 1) * out.grad. Now a/b gives 0.5. Subtraction is built from what exists: a − b is a + (−b), and negation is multiplication by −1.

    def exp(self):
    out = Value(math.exp(self.data), (self,), 'exp')
    def _backward():
        self.grad += out.data * out.grad          # d/dx e^x = e^x
    out._backward = _backward
    return out

def __pow__(self, other):                         # other: an int or float
    out = Value(self.data**other, (self,), f'**{other}')
    def _backward():
        self.grad += other * self.data**(other - 1) * out.grad   # power rule
    out._backward = _backward
    return out

def __truediv__(self, other): return self * other**-1
def __neg__(self): return self * -1
def __sub__(self, other): return self + (-other)

    Following the lecture notebook (MIT licence).

    Notice which operations needed new backward code: only exp and __pow__. Division, negation and subtraction are built from multiplication, powers and addition, so they get correct gradients for free — the chain rule runs through their parts. The exponent must be a plain number because the power rule is the derivative with respect to the base; an exponent that was itself a Value would need a second derivative rule.

    tanh, taken apart

    The same forward pass and the same gradients — granularity is a choice

    In the lectureNow rewrite the neuron’s output with tanh’s formula: e = (2·n).exp(), then o = (e − 1)/(e + 1), with e as an intermediate variable because it’s used twice. The graph gets much longer — exp, plus, times −1, the power of −1 for the division, times — but it is mathematically equivalent, so we expect the same forward pass and the same gradients. And so it is: o is 0.7071, and the leaves get w2 0, x2 0.5, w1 1, x1 −1.5. The point: the level at which you implement your operations is totally up to you. A single plus, a single times, or a composite like tanh — “all of this is kind of like a fake concept”. All that matters is that an output is a function of some inputs, and that you can do that operation’s forward pass and backward pass. If you can write the local gradients, you can chain them and continue backpropagation.

    Elsewhere in these notesPart 3 made this claim (part 3, move 4), and its exercise 4 checked the values. Here the gradients agree too, through a graph twice the size. Build it, exercise 4, runs it.

    The same thing in PyTorch

    Tensors, double precision, requires_grad — and the same numbers

    In the lecturemicrograd is roughly modelled on PyTorch, a library you would use in production. micrograd is a scalar-valued engine, but in PyTorch everything is built around tensors, n-dimensional arrays of scalars — a 2 × 3 array, say, with its .shape. So each value becomes a one-element tensor, cast with .double() to 64-bit floats like Python’s, because PyTorch’s default type is float32, single precision. Leaf tensors don’t require gradients by default — for efficiency, since you usually don’t want gradients for leaves like the network’s inputs — so each one is told requires_grad = True. After that, the arithmetic is the same, there’s a torch.tanh, and the result is a tensor with .data and .grad, just like micrograd. .item() takes a one-element tensor and returns the plain number inside. Running it prints a forward pass of 0.707 and gradients of 0.5, 0, −1.5 and 1: “PyTorch agrees with us.” PyTorch can do what micrograd does as a special case, with one-element tensors; the big deal is that it’s far more efficient, working on whole tensors in parallel.

    import torch
x1 = torch.Tensor([2.0]).double();                x1.requires_grad = True
x2 = torch.Tensor([0.0]).double();                x2.requires_grad = True
w1 = torch.Tensor([-3.0]).double();               w1.requires_grad = True
w2 = torch.Tensor([1.0]).double();                w2.requires_grad = True
b  = torch.Tensor([6.8813735870195432]).double(); b.requires_grad = True
n = x1*w1 + x2*w2 + b
o = torch.tanh(n)

print(o.data.item())
o.backward()
print('x2', x2.grad.item())
print('w2', w2.grad.item())
print('x1', x1.grad.item())
print('w1', w1.grad.item())

    As in the lecture. Not run on this page: PyTorch isn’t needed for this series, and micrograd is the point.

    Watch forIf you run this and the far decimals differ slightly from micrograd’s, that’s the precision, not the method: torch.Tensor([…]) makes a float32 tensor first, so the bias is rounded to single precision before .double() widens it. torch.tensor([…], dtype=torch.float64) keeps all the digits. And .item(), PyTorch’s documentation notes, “only works for tensors with one element” (torch.Tensor.item).

    A Neuron

    Random weights, a bias, and __call__ for w·x + b

    In the lectureWith machinery for complicated expressions, we can build neural nets — “just a specific class of mathematical expressions” — piece by piece, up to a two-layer multi-layer perceptron, and match PyTorch’s neural-network module API the way the engine matched its autograd. class Neuron: the constructor takes the number of inputs and creates a weight for each, a random number between −1 and 1, and a bias for the overall trigger happiness. __call__ makes n(x) work: Python calls it when you use the object like a function. The forward pass is w·x + b: zip pairs each weight with its input, the products are summed, the bias is added, and the result goes through tanh. Each new neuron gives a different output, because its weights are random. A neat detail: sum takes an optional start value, 0 by default, so the sum can simply start at self.b — with the generator expression in parentheses.

    class Neuron:
    def __init__(self, nin):
        self.w = [Value(random.uniform(-1, 1)) for _ in range(nin)]
        self.b = Value(random.uniform(-1, 1))

    def __call__(self, x):
        # w * x + b
        act = sum((wi*xi for wi, xi in zip(self.w, x)), self.b)
        out = act.tanh()
        return out

    From the lecture notebook (MIT licence). micrograd’s own nn.py starts its weights the same way, with random.uniform(-1, 1).

    Layer and MLP

    Neurons side by side, then layers in sequence

    In the lectureIn an MLP layer, the neurons aren’t connected to each other, but each is fully connected to the input. So a layer is just a set of neurons evaluated independently: a list of nout neurons, each with nin inputs, all called on the same x. A layer of three two-input neurons gives three independent outputs. In an MLP, the layers feed into each other sequentially: it takes the number of inputs and a list of output sizes, one per layer, pairs consecutive sizes to create the layers, and calls them in order. The lecture’s picture is three inputs, two layers of four, and one output: MLP(3, [4, 4, 1]). One convenience: a layer returns its single output on its own, not wrapped in a list, when it has only one neuron.

    class Layer:
    def __init__(self, nin, nout):
        self.neurons = [Neuron(nin) for _ in range(nout)]

    def __call__(self, x):
        outs = [n(x) for n in self.neurons]
        return outs[0] if len(outs) == 1 else outs

class MLP:
    def __init__(self, nin, nouts):
        sz = [nin] + nouts
        self.layers = [Layer(sz[i], sz[i+1]) for i in range(len(nouts))]

    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

x = [2.0, 3.0, -1.0]
n = MLP(3, [4, 4, 1])
n(x)

    Graphs that branch

    Section 7.4.3: any acyclic graph — and the line that runs it all

    The book’s backpropagation so far worked on a network that is naturally sequential: f0, h1, f1, … in turn. Section 7.4.3 notes that models need not be sequential. Later chapters meet networks that branch — taking a hidden layer through two different sub-networks and recombining them — and fortunately the ideas of backpropagation still hold if the computational graph is acyclic. Frameworks such as PyTorch and TensorFlow handle arbitrary acyclic graphs.

    Section 7.6 then shows a complete PyTorch training script — a model, He initialisation, a least-squares loss, SGD with momentum — and draws the moral: the ideas are complex, but the implementation is simple, because “all of the details of the backpropagation are hidden in the single line of code: loss.backward()”.

    Lecture ↔ bookBranching is exactly where move 5’s += matters. A value that feeds two branches receives one gradient from each, and the multivariable chain rule says they add (chain rule, multivariable case). micrograd’s topological sort (move 3) already handles any acyclic graph; += makes the gradients right on it.

    Why starting weights matter

    Section 7.5: vanishing and exploding, forwards and backwards

    Before training starts, every weight and bias needs a value — and section 7.5 shows why the choice is crucial. In the forward pass each layer computes fk = βk + Ωka[fk−1]. Set the biases to zero and draw the weights from a normal distribution with mean zero and variance σ². If σ² is very small (say 10−5), each layer’s outputs are weighted sums with tiny weights, smaller than their inputs — and the ReLU halves the range besides — so the values shrink layer after layer. If σ² is very large (105), they grow layer after layer. Either way they can become too small or too large for floating-point numbers to represent.

    The backward pass has the same problem, because each step multiplies by ΩT. Badly initialised weights make the gradients shrink or grow uncontrollably as they travel back: the vanishing gradient problem, where updates become vanishingly small, and the exploding gradient problem, where they become unstable.

    He initialisation

    Sections 7.5.1–7.5.3: a weight variance of 2/D keeps the signal steady

    Section 7.5.1 turns the argument into a formula. With zero biases and weights of variance σΩ², the pre-activations in the next layer have mean zero, and — since the ReLU clips half of a symmetric distribution — a variance of

    σf′² = ½ · Dh · σΩ² · σf²Dh is the number of units feeding in

    So to keep the variance the same from layer to layer, choose σΩ² = 2/Dh: He initialisation. Section 7.5.2 runs the same argument backwards, through ΩT, and gets 2/Dh′, using the size of the layer the weights feed into. When the two sizes differ, both can’t hold at once, and section 7.5.3 suggests a compromise, the average:

    σΩ² = 4 / (Dh + Dh′)

    The book’s figure 7.7 checks it on a network of 50 layers of 100 units: with 2/Dh = 0.02 the variance of the activations, and of the gradients, stays stable; larger values blow up, and smaller ones die away — what the lab in move 14 reproduces. The companion is notebook 7.3, Initialization.

    Lecture ↔ bookmicrograd’s Neuron draws weights from uniform(−1, 1), whose variance is 1/3. For a neuron with three or four inputs that is roughly 1/D, so the sums stay in tanh’s working range; for networks with hundreds of inputs per neuron, the same draw would push tanh into its flat tails, where gradients vanish (part 3, move 6) — which is why real libraries scale the starting weights to each layer’s size.

    Beyond the bookHe initialisation is named after Kaiming He and colleagues, who introduced it in 2015 for very deep ReLU networks (“Delving deep into rectifiers”). The book’s notes say it follows closely from Xavier Glorot and Yoshua Bengio’s initialisation of 2010, which is very similar but ignores the effect of the ReLU, and so differs by a factor of two.

    Exercise 1 · moves 1–2

    Backward steps, called by hand

    Give Value a _backward that defaults to doing nothing, and closures for +, × and tanh. Build the neuron, set o.grad = 1, and call each node’s _backward in the right order.

    One way to write it 
    import math

class Value:
    def __init__(self, data, _children=(), _op='', label=''):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None          # a leaf has nothing to pass on
        self._prev = set(_children)
        self._op = _op
        self.label = label

    def __add__(self, other):
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad = 1.0 * out.grad
            other.grad = 1.0 * out.grad
        out._backward = _backward              # store the function, don't call it
        return out

    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad = other.data * out.grad
            other.grad = self.data * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = (math.exp(2 * self.data) - 1) / (math.exp(2 * self.data) + 1)

    Exercise 2 · moves 3–4

    backward()

    Add a backward method that builds the topological order from self, sets self.grad = 1 and runs every _backward in reverse. Print the last three nodes in the order, and the gradients.

    One way to write it 
    import math

class Value:
    def __init__(self, data, _children=(), _op='', label=''):
        self.data, self.grad = data, 0.0
        self._backward = lambda: None
        self._prev, self._op, self.label = set(_children), _op, label

    def __add__(self, other):
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad = out.grad
            other.grad = out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad = other.data * out.grad
            other.grad = self.data * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,), 'tanh')
        def _backward():
            self.grad = (1 - t**2) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        topo, visited = [], set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)              # only after all of v's children
        build_topo(self)
        self.grad = 1.0
        for node in reversed(topo):
            node._backward()
        return topo

    Find the bug, then fix it

    Run b = a + a and f = (a·b)·(a + b) with grads that are set, then with grads that are accumulated. Check the second against nudging.

    One way to write it 
    class Value:
    ACCUMULATE = False
    def __init__(self, data, _children=()):
        self.data, self.grad = data, 0.0
        self._backward = lambda: None
        self._prev = list(_children)        # a list, not a set, so the buggy run is repeatable

    def _deposit(self, g):
        if Value.ACCUMULATE:
            self.grad += g                     # the fix
        else:
            self.grad = g                      # the bug: overwrites

    def __add__(self, other):
        out = Value(self.data + other.data, (self, other))
        def _backward():
            self._deposit(out.grad); other._deposit(out.grad)
        out._backward = _backward
        return out

    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other))
        def _backward():
            self._deposit(other.data * out.grad); other._deposit(self.data * out.grad)
        out._backward = _backward
        return out

    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for c in v._prev: build(c)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo): v._backward()

    Exercise 4 · moves 6–8

    More operations, and tanh taken apart

    Let + and × accept plain numbers; add __rmul__, exp, __pow__, __truediv__, __neg__ and __sub__. Then build the neuron with o = (e − 1)/(e + 1), e = (2n).exp(), and compare its gradients with tanh’s.

    One way to write it 
    import math

class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data, self.grad = data, 0.0
        self._backward = lambda: None
        self._prev, self._op = set(_children), _op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)   # wrap plain numbers
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def __pow__(self, other):                  # other: a plain int or float
        out = Value(self.data**other, (self,), f'**{other}')
        def _backward():
            self.grad += other * self.data**(other - 1) * out.grad   # the power rule
        out._backward = _backward
        return out

    def exp(self):
        out = Value(math.exp(self.data), (self,), 'exp')
        def _backward():
            self.grad += out.data * out.grad   # d/dx e^x = e^x
        out._backward = _backward
        return out

    def __rmul__(self, other): return self * other          # 2 * a  ->  a * 2
    def __truediv__(self, other): return self * other**-1   # a / b = a * b**-1
    def __neg__(self): return self * -1
    def __sub__(self, other): return self + (-other)

    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for c in v._prev: build(c)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo): v._backward()

    Exercise 5 · moves 10–12

    Neuron, Layer, MLP

    Write the three classes, build MLP(3, [4, 4, 1]) with random.seed(42), run it on [2.0, 3.0, −1.0], count its parameters and the Values in its graph, and backpropagate.

    One way to write it 
    import math
import random

class Value:
    def __init__(self, data, _children=()):
        self.data, self.grad = data, 0.0
        self._backward = lambda: None
        self._prev = set(_children)

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))
        def _backward():
            self.grad += out.grad; other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))
        def _backward():
            self.grad += other.data * out.grad; other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def __radd__(self, other): return self + other
    def __rmul__(self, other): return self * other

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,))
        def _backward():
            self.grad += (1 - t**2) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for c in v._prev: build(c)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo): v._backward()
        return topo


class Neuron:
    def __init__(self, nin):
        self.w = [Value(random.uniform(-1, 1)) for _ in range(nin)]
        self.b = Value(random.uniform(-1, 1))

    def __call__(self, x):
        act = sum((wi * xi for wi, xi in zip(self.w, x)), self.b)   # w·x + b
        return act.tanh()

class Layer:
    def __init__(self, nin, nout):
        self.neurons = [Neuron(nin) for _ in range(nout)]

    def __call__(self, x):
        outs = [n(x) for n in self.neurons]
        return outs[0] if len(outs) == 1 else outs

class MLP:
    def __init__(self, nin, nouts):
        sz = [nin] + nouts
        self.layers = [Layer(sz[i], sz[i + 1]) for i in range(len(nouts))]

    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

x = [2.0, 3.0, -1.0]
net = MLP(3, [4, 4, 1])
out = net(x)
params = [p for L in net.layers for n in L.neurons for p in n.w + [n.b]]
print("output:", round(out.data, 6))
print("parameters:", len(params))
nodes = out.backward()
print("Values in the graph:", len(nodes))
print("first neuron's weight grads:", [round(w.grad, 4) for w in net.layers[0].neurons[0].w])

    Vanishing and exploding, in plain Python

    Push a random input through 50 ReLU layers of 100 units with zero biases and weight variances 0.01, 0.02 and 0.1, and print the variance at layers 10, 30 and 50.

    One way to write it 
    import math
import random

# UDL section 7.5: a deep ReLU network, 50 layers of 100 units, biases 0,
# weights drawn with mean 0 and variance s2. How big are the activations deep down?
random.seed(1)
D, L = 100, 50
x = [random.gauss(0, 1) for _ in range(D)]

for s2 in [0.01, 0.02, 0.1]:
    sd = math.sqrt(s2)
    h, report = x, []
    for k in range(1, L + 1):
        W = [[random.gauss(0, sd) for _ in range(D)] for _ in range(D)]
        f = [sum(w * v for w, v in zip(row, h)) for row in W]
        h = [max(0.0, v) for v in f]
        if k in (10, 30, 50):
            var = sum(v * v for v in f) / D
            report.append(f"layer {k}: {var:.2e}")
    print(f"variance {s2}: " + ", ".join(report))
    variance 0.01: layer 10: 2.63e-03, layer 30: 2.04e-09, layer 50: 1.28e-15
variance 0.02: layer 10: 9.60e-01, layer 30: 2.61e-01, layer 50: 1.17e+00
variance 0.1: layer 10: 1.33e+07, layer 30: 1.52e+20, layer 50: 3.09e+34

    0.02 is 2/100, He initialisation: the variance drifts a little from layer to layer but stays around 1 all the way down. Half that, and it dies away by fifteen orders of magnitude; five times that, and it grows by thirty-four.

    Check yourself

    Sixteen questions: tap an answer to see the reason. Your first tap on each question is the one that counts.

    1. What does a node’s _backward do?

    The little piece of chain rule at each node: local derivative × out.grad (move 1).

    2. What is a leaf’s _backward?

    A leaf has no inputs to pass a gradient to (moves 1–2).

    3. “’NoneType’ object is not callable” came from…

    The function returns None; that None got stored and later called (move 2).

    4. Why must o.grad be set to 1 before calling o._backward()?

    It is the base case: dO/dO = 1 (move 2).

    5. In a topological order built by build_topo, a node appears…

    It appends itself after recursing into its children: the invariant (move 3).

    6. Why does backward() loop over reversed(topo)?

    Reversed, the output comes first and every node waits for all its users (moves 3–4).

    7. With = in the backward steps, b = a + a gives a.grad = …

    self and other are the same object: the second deposit overwrites the first (move 5).

    8. What fixes it?

    The multivariate chain rule: contributions from each use add (move 5).

    9. 2 * a works because Python falls back to…

    The reflected method, which swaps the operands and returns a * 2 (move 6).

    10. The local derivative used in exp’s backward step is…

    d/dx ex = ex, already stored in out.data (move 7).

    11. How is a / b computed?

    Division is a special case of the power rule, so it needs no backward code of its own (move 7).

    12. Breaking tanh into exp, plus and divide changes the gradients by…

    Mathematically equivalent operations give the same forward and backward passes (move 8).

    13. Why does PyTorch need requires_grad = True on the leaves?

    Usually you don’t want gradients for inputs, so the default is off (move 9).

    14. In Neuron.__call__, what does sum(…, self.b) do?

    sum’s optional start value: w·x + b in one expression (move 10).

    15. How many parameters does MLP(3, [4, 4, 1]) have?

    4·(3+1) + 4·(4+1) + 1·(4+1) = 16 + 20 + 5. 126 is the number of Values one forward pass builds (move 12).

    16. In a 50-layer ReLU network of width 100, weight variance 0.1 makes the activations…

    He initialisation is 2/100 = 0.02; five times that grows the signal at every layer (moves 14–15).

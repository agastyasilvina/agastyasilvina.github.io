Toward multi-layer perceptrons

Where the series is heading: layers of neurons, fully connected

In the lectureThe aim is to build up neural networks, and in the simplest case these are multi-layer perceptrons, as they’re called. The picture is a two-layer neural net: hidden layers made up of neurons, and the neurons fully connected to the ones in the next layer.

You have met this picture already, in the book’s words: hidden units, hidden layers, fully connected, and the historical name “multi-layer perceptron” for any network with at least one hidden layer (part 1, move 20). The lecture now builds the smallest piece of it, one neuron, out of the Value objects of part 2.

2

A model of a neuron

Weights, the bias’s “trigger happiness”, and a squashing function

In the lectureBiologically, neurons are very complicated devices, but we have very simple mathematical models of them. There are some inputs, the xs, and synapses that carry weights, the ws. The synapse interacts with its input multiplicatively, so what flows to the neuron’s cell body is w times x — many of them, one per input. The cell body also has a bias, “the innate sort of trigger happiness of this neuron”: it can make the neuron a bit more or a bit less trigger happy, regardless of the input. Add up all the w·x and the bias, then pass the result through an activation function, usually some kind of squashing function, like a sigmoid or tanh. The lecture uses tanh, plotted with NumPy’s np.tanh: exactly 0 at 0, rising for positive inputs but only up to 1, where it plateaus — very positive inputs are capped smoothly at 1, very negative ones at −1. What comes out of the neuron is the activation function applied to the dot product of the weights and the inputs, plus the bias.

o = tanh(w1x1 + w2x2 + … + b)weights times inputs, plus the bias, squashed into (−1, 1)
Try it — the squashing function

Move n, the raw sum going into the neuron. The curve is tanh; the orange line is its slope at n, 1 − tanh²(n) — the local derivative backpropagation will need. Watch what happens to the slope out in the tails.

Beyond the lectureThe neuron picture comes from Stanford’s CS231n course notes, which describe the same model — the weights as “synaptic strengths”, and each neuron performing “a dot product with the input and its weights”, adding the bias and applying the activation — and add a warning: “It’s important to stress that this model of a biological neuron is very coarse.” On tanh they note that, like the sigmoid, “its activations saturate, but unlike the sigmoid neuron its output is zero-centered”, so “in practice the tanh non-linearity is always preferred to the sigmoid nonlinearity” — while their summary expects both to work worse than the ReLU (CS231n, “Neural Networks Part 1”).

Lecture ↔ bookThe book’s hidden unit is the same model with a ReLU instead of tanh (part 1, move 17), and part 1’s activation figure puts tanh, the sigmoid and the ReLU side by side (move 20).

One neuron in code

x1·w1 + x2·w2 + b, built in small steps

In the lectureThe code (copy-pasted, “because I don’t want to type too much”) is a two-dimensional neuron: inputs x1 and x2, weights w1 and w2 — the synaptic strengths for each input — and the bias b. The model says multiply x1 by w1 and x2 by w2, then add the bias. It looks a little messy because it’s done in small steps, so that there are pointers to all the intermediate nodes: x1w1 and x2w2, each labelled, then their sum, then n, the cell body’s raw activation before any activation function. draw_dot(n) shows x1·w1 and x2·w2 being added and the bias added on top.

Every intermediate value gets its own name because every intermediate value is a node the backward pass will visit. Writing x1*w1 + x2*w2 + b in one line would build exactly the same graph; the names are only there so you can point at the nodes.

4

tanh, at any level of abstraction

One node for a whole function — as long as you know its local derivative

In the lectureThe output should be o = n.tanh(), but Value has no tanh yet. tanh is a hyperbolic function, and you can’t make it out of just pluses and times: its formula needs exponentiation. One option would be to implement exp, and then build tanh from exp, plus and times. But Karpathy specifically wants to show that we don’t need the most atomic pieces in the value object: we can create functions at arbitrary points of abstraction, complicated or as simple as a plus. The only thing that matters is that we know how to differentiate through it: if you know the local derivative — how the inputs impact the output — that’s all you need. So the whole expression is clustered into one operation: tanh computes t = (e2x − 1)/(e2x + 1) from self.data, with a single child, wrapped in a tuple, (self,), and the op name 'tanh'. Now draw_dot(o) shows n going through tanh to give the output. In action: with the bias at 8, n = 2 flows in and tanh squashes it to 0.96 — already the tail. Then the bias changes to “something slightly strange”, 6.8813…, so that the numbers come out nice for backpropagation: 0.88 flows into tanh and 0.7071 comes out.

def tanh(self):
    x = self.data
    t = (math.exp(2*x) - 1)/(math.exp(2*x) + 1)
    out = Value(t, (self, ), 'tanh')
    return out

The lecture’s tanh at this stage, from the notebook (MIT licence); part 4 gives it a backward step.

This is a design principle, not a shortcut. A node is a contract: given its inputs, produce an output, and know how the output responds to each input. Whether that’s a plus or a whole tanh is a choice of granularity — fewer, bigger nodes are faster; smaller ones need less calculus. Build it, exercise 4, builds tanh both ways and gets the same numbers.

Beyond the lectureWhy 6.8813735870195432? The aim is o = tanh(n) = 1/√2 ≈ 0.7071, because then 1 − o² is exactly a half. The n that does it is artanh(1/√2) = ln(1 + √2) ≈ 0.8813735870. With x1·w1 = 2 × −3 = −6 and x2·w2 = 0, the bias has to be 6 + 0.8813735870… — which is the strange number.

Arc B · The lecture: backpropagation through a neuron

4 moves
5

What we’re after

The weights’ derivatives — one neuron in a much bigger puzzle

In the lectureNow backpropagation fills in all the gradients: the derivative of o with respect to everything that went into it. In a typical neural network, what we care about most is the derivative with respect to the weights, w1 and w2, because those are what we change as part of the optimisation. And this is only a single neuron. A real network has many, connected, and this is “one small piece of a much bigger puzzle”: eventually there’s a loss function that measures the accuracy of the network, and we backpropagate with respect to that accuracy, trying to increase it.

So keep two pictures at once. In this example the output o plays the role of the thing we differentiate; in training, that role belongs to the loss, and o is just one node somewhere upstream of it. Nothing about the procedure changes — only which node gets the starting grad of 1.

6

Through tanh

The base case, then do/dn = 1 − o² = 0.5

In the lectureStart at the end, with the base case that never changes: o.grad = 1. To go back through tanh we need its local derivative: if o = tanh(n), what is do/dn? You could take the calculus derivative of the formula, or scroll down Wikipedia to the derivative of tanh: 1 − tanh²(x). tanh of n is just o, so do/dn = 1 − o². o.data is 0.7071, and 1 − o² is, “conveniently”, 0.5. So n.grad = 0.5, exactly a half.

o = tanh(n)  ⟹  do/dn = 1 − o² = 1 − 0.7071² = 0.5the local derivative is computed from the output, which the forward pass already stored

Notice that the local derivative is written in terms of o, the node’s own output. The backward step doesn’t need to recompute tanh; it reuses the value from the forward pass. That is the book’s observation 1 again (part 2, move 12): store the forward pass, and the backward pass gets cheaper.

Beyond the lectureThe shape of 1 − o² explains a lot. It is 1 when n = 0 and falls towards 0 as tanh flattens out at ±1: by n = 4 about a thousandth of the gradient gets through (Build it, exercise 5). A neuron pushed far into its tail is saturated, and passes back almost nothing, so its weights barely learn. It is one reason networks are initialised with small weights, and one reason the ReLU, whose slope is a full 1 for every positive input, displaced tanh in deep networks (part 1, move 20).

7

Pluses distribute

0.5 flows to the bias, and on to both products

In the lecturen is a plus node. From the previous example, a plus is just a distributor of gradient: its local derivative is 1 for each input, so 1 × 0.5 = 0.5 flows to both. The sum x1w1 + x2w2 gets grad 0.5, and so does b. Another plus: 0.5 again flows to both x1w1 and x2w2. “Pluses are my favourite operations to backpropagate through, because it’s very simple.” And remember what each derivative says: if we want this neuron’s output to increase, these expressions’ influence on it is positive — both contribute positively.

The bias’s gradient deserves a second look: b.grad equals n.grad, always, for any neuron. The bias adds straight into the sum, so it gets the full gradient that reaches the sum. That’s the plus node’s routing, and it is also the book’s ∂ℓ/∂βk = ∂ℓ/∂fk (move 14).

8

Times nodes, and a zero

w2.grad = 0 because x2 = 0, and w1.grad = 1

In the lectureNow the times nodes, where the local derivative is the other term. x2.grad = w2.data × x2w2.grad = 1 × 0.5 = 0.5, and w2.grad = x2.data × x2w2.grad = 0 × 0.5 = 0. The weight’s gradient is 0 because x2’s data was 0 — and intuitively that’s right: the derivative tells us the influence on the final output, and if you wiggle w2, the output doesn’t change, because w2 is multiplied by 0. Then x1.grad = w1 × 0.5 = −1.5 and w1.grad = x1 × 0.5 = 1. Those are the final derivatives. Reading them: to make this neuron’s output increase, w2 doesn’t matter right now, but w1 should go up, and the output would rise proportionally, because its gradient is 1. Then: “doing the backpropagation manually is obviously ridiculous”, so the lecture puts “an end to this suffering” and implements the backward pass automatically — part 4.

Try it — backpropagate through the neuron

The lecture’s neuron, top-down: inputs and weights at the top, o at the bottom. Step backwards from o, one node at a time, then check the leaves by nudging. Change any input, or set x2 to something other than 0 and watch w2 come alive.

One thing the numbers hide: x1 and x2 got gradients too. Here they are data, so nobody will change them. But in a network, x1 would be the output of another neuron, and its gradient, −1.5, is exactly the message that neuron needs to adjust its own weights. That is how blame travels through hidden layers — which is where arc C begins.

Arc C · Why networks need backpropagation

5 moves
9

Training needs a slope for every weight

What backpropagation is for, in one move

This arc steps outside the lecture. Start from what training is. A network is a mathematical expression of the data and the weights, ending in a loss: one number saying how wrong the network is on the training examples (part 1, move 3). Training means changing the weights so that the loss goes down, over and over. The question at every single step is: which way should each weight move, and how much?

The answer is the gradient: ∂L/∂w for every weight w. With it, one step of gradient descent moves every weight a little against its own slope, w ← w − α·∂L/∂w (part 1, move 10). So training needs, at every step, a slope for every weight — and modern networks have millions or billions of weights, and are trained for thousands or millions of steps.

Backpropagation is the algorithm that produces those slopes. It doesn’t decide how to update the weights; that’s the optimiser’s job, gradient descent or one of its relatives. Backprop only answers the question each step asks: how does the loss respond to each weight, right now?

10

Four ways to get the slopes

Guess, nudge, derive, or backpropagate

There are only a few ways to get ∂L/∂w for every weight, and the comparison is the clearest answer to “why backprop?”.

  • Guess and check. Change the weights at random and keep changes that help. It works for a handful of weights and collapses in a million dimensions, where almost every random direction is useless.
  • Nudge each weight — part 1’s method. Correct, but it costs one extra forward pass per weight, per step: a network with a billion weights would need a billion forward passes for one step of training (Build it, exercise 6, counts them).
  • Derive a formula for each weight. Exact, but the formulas grow huge and repeat the same pieces over and over — the book’s formula for one derivative of its toy model already ran to three lines (part 2, move 13).
  • Backpropagate. One forward pass, storing the intermediate values, and one backward pass, applying each node’s local derivative: every slope, exactly, for a cost of a few forward passes — however many weights there are.
Try it — what a gradient costs

Pick a model size and how long one forward pass takes. Nudging needs one forward pass per weight, plus one; backprop costs roughly three forward passes, whatever the size. The forward-pass time is held fixed so the comparison stays fair.

Beyond the lectureThe “few forward passes” has numbers behind it. The standard survey of automatic differentiation puts it this way: forward mode “requires n evaluations to compute the gradient”, while “only one application of the reverse mode is sufficient to compute the full gradient”, at a cost that is a constant times one evaluation, with the constant “guaranteed to be c < 6 and typically c ∼ [2, 3]” (Baydin and colleagues, 2018). Andreas Griewank calls this the principle that gradients can “always” be computed at a small multiple of the cost of the function, “irrespective of n” (Griewank, 2012). For large language models, the backward pass costs “approximately twice the compute as the forwards pass”, so a training step is about three forward passes’ worth (Kaplan and colleagues, 2020). The lab’s model sizes: GPT-2’s largest version has 1.5 billion parameters (model card), GPT-3 has 175 billion (Brown and colleagues, 2020), and the digit classifier is a 784–100–10 network: 78,400 + 100 + 1,000 + 10 parameters.

11

Credit assignment

Hidden neurons have no targets: who gets the blame?

The second reason goes deeper than speed. In a network with hidden layers, the training data says what the output should be, but nothing says what a hidden neuron should have done. When the output is wrong, which of the thousands of weights deep inside deserve the blame, and how much? That’s the credit assignment problem.

Backpropagation answers it exactly. A hidden neuron’s gradient is its share of the blame, passed back to it by the chain rule through every path to the loss — which is what x1’s −1.5 in move 8 would be, if x1 were another neuron’s output. And the answer can be zero: move 8’s w2 got no blame because it had no effect. That’s not a failure of the method; it is the method telling the truth.

Beyond the lectureThe name comes from Marvin Minsky’s 1961 paper “Steps Toward Artificial Intelligence”, under the heading “The Credit-Assignment Problem for Learning Systems”: “If the run is successful, how can we assign credit for the success among the multitude of decisions?” (Minsky, 1961). The early perceptrons dodged the problem rather than solving it: in Frank Rosenblatt’s Mark I, the connections into the hidden layer were fixed, not learned, and Minsky and Seymour Papert’s book Perceptrons (1969) analysed what such single-layer learners could not do (overview — the popular story that the book “killed” neural networks is a simplification). Backpropagation’s answer is what made the 1986 paper by David Rumelhart, Geoffrey Hinton and Ronald Williams famous: “internal ‘hidden’ units which are not part of the input or output come to represent important features of the task domain … The ability to create useful new features distinguishes back-propagation from earlier, simpler methods such as the perceptron-convergence procedure” (Nature, 1986).

12

Why backwards?

One loss, many weights: reverse mode, and its memory bill

The chain rule doesn’t care which end you start from. You could carry derivatives forwards, from one weight through the network to the loss, as nudging does in spirit; this is forward mode, and it needs one sweep per weight. Or you can carry them backwards, from the loss to every weight at once: reverse mode, which is backpropagation, and needs one sweep per output.

A network has one loss and millions of weights, so the backwards direction wins by a factor of millions. It also reuses work: every path from a weight to the loss passes through the layers after it, and the backward pass computes each layer’s gradient once and shares it with everything before it — the book’s observation 2 (part 2, move 12).

The price is memory. Every local derivative needs values from the forward pass — the stored o in move 6, the other input of every times node — so all of them must be kept until the backward pass has used them. For big models, that memory, not the arithmetic, is often the limit (move 15).

Beyond the lectureThe memory price is in the survey too: reverse mode comes with “increased storage requirements growing (in the worst case) in proportion to the number of operations” (Baydin and colleagues). And the backwards idea is older than neural networks. Henry J. Kelley (1960) and Arthur Bryson (1961) used precursors of it in control theory; Stuart Dreyfus (1962) derived it with only the chain rule; Seppo Linnainmaa first published the modern reverse mode in a 1970 master’s thesis; and Paul Werbos discussed it for neural networks in 1974 and described the efficient version for them in 1982 — years before the 1986 paper made it the way networks are trained (Schmidhuber’s history; Griewank).

13

Neural networks and deep learning

“Deep” means many layers — and backprop is what makes them trainable

Where do neural networks sit? Artificial intelligence is the broad project; machine learning is the part of it that learns from data by fitting models; and deep learning is machine learning with one particular family of models, deep neural networks (part 1, move 11).

“Deep” simply means many layers. A shallow network has one hidden layer; a deep one stacks many, each taking the previous layer’s output as its input. The stacking is the point: each layer can build its features out of the features below it, and depth makes far more complex functions from the same number of parameters (part 1, moves 21 and 24).

But a deep network is only useful if you can train it, and training means getting a gradient for every weight in every layer — which is exactly the credit-assignment problem of move 11, and exactly what backpropagation solves. So the relationship is close to definitional: neural networks are the models, deep learning is the practice of training deep ones, and backpropagation plus gradient descent is the engine that does the training.

Beyond the lectureTwo standard definitions say the same thing from two sides. Yann LeCun, Yoshua Bengio and Geoffrey Hinton: “Deep learning allows computational models that are composed of multiple processing layers to learn representations of data with multiple levels of abstraction” — and it does so “by using the backpropagation algorithm to indicate how a machine should change its internal parameters” in each layer (Nature, 2015). Ian Goodfellow, Yoshua Bengio and Aaron Courville: concepts built out of simpler ones form a graph that “is deep, with many layers. For this reason, we call this approach to AI deep learning” (Deep Learning, 2016).

Backpropagation made multi-layer networks trainable in the 1980s, but, the book notes, progress then stalled, in hindsight for want of data, computing power and better activations than the sigmoid. The modern era began in 2012, when Alex Krizhevsky, Ilya Sutskever and Geoffrey Hinton’s network “achieved a winning top-5 test error rate of 15.3%, compared to 26.2% achieved by the second-best entry” in the ImageNet competition — trained by backprop on two GPUs over five to six days, with ReLUs and dropout (the AlexNet paper).

Backprop for a whole network

Section 7.4: vectors, matrices and the ReLU switch

Section 7.4 repeats the toy model’s derivation (part 2, move 14) for a real network with three hidden layers. The algebra is the same; what changes is that the intermediate values fk and hk and the biases βk are now vectors, the weights Ωk are matrices, and the activation is the ReLU rather than cos or exp.

The forward pass computes and stores f0 = β0 + Ω0x, then hk = a[fk−1] and fk = βk + Ωkhk layer by layer, ending with the loss. Backward pass #1 computes ∂ℓ/∂fk from the end, and each step back does two simple things in turn: it multiplies by the transposed weight matrix ΩkT, and it applies the ReLU’s switch. The ReLU’s derivative is 0 where its input was negative and 1 where it was positive, so instead of a matrix multiplication it’s a mask, I[fk−1 > 0], multiplied pointwise. Backward pass #2 then reads off the parameters:

∂ℓ/∂βk = ∂ℓ/∂fk    ∂ℓ/∂Ωk = (∂ℓ/∂fk) hkTthe bias gets the gradient unchanged; each weight gets the gradient times the activation it multiplied

Lecture ↔ bookThat is the neuron of move 8, a layer at a time. b.grad = n.grad is ∂ℓ/∂βk = ∂ℓ/∂fk; w1.grad = x1 × 0.5 is the outer product with hk; and w2.grad = 0 because x2 = 0 is what the outer product does to any weight whose input was 0. A ReLU in the tail behaves like tanh in its tail (move 6), only more abruptly: where the input was negative, the mask lets nothing back.

15

Every piece knows its own derivative

Sections 7.4.1–7.4.3: the algorithm in brief, and frameworks that do it for you

Section 7.4.1 sums the algorithm up: a forward pass that computes and stores every fk and hk, then a backward pass from ∂ℓ/∂fK down to the first layer that produces ∂ℓ/∂βk and ∂ℓ/∂Ωk, repeated for every example in the batch and summed for the SGD update. It is extremely efficient — the heaviest steps in both directions are matrix multiplications, by Ω and ΩT — but not memory-efficient: every intermediate value from the forward pass must be stored, and that can limit the size of model you can train.

Section 7.4.2 adds that you will rarely code this yourself. Frameworks such as PyTorch and TensorFlow compute the derivatives automatically from the model’s specification — algorithmic differentiation — because each component knows how to compute its own derivative: a ReLU knows its output’s derivative with respect to its input, and a linear layer knows its derivatives with respect to its input and its parameters. The framework also knows the order of the operations, which is everything the forward and backward passes need. GPUs run the matrix multiplications in parallel, for a whole batch at once, which is why the data becomes a tensor with an extra batch dimension. Section 7.4.3 notes that none of this requires a simple chain of layers: the same ideas work for networks that branch and recombine.

Lecture ↔ book“Each component knows how to compute its own derivative” is Karpathy’s point in move 4, word for word in spirit: tanh can be one node because it knows its local derivative. micrograd is a tiny algorithmic-differentiation framework, and part 4 is where it learns to run the backward pass by itself.

One way to write it 
import math

class Value:
    def __init__(self, data, _children=(), _op='', label=''):
        self.data = data
        self.grad = 0.0
        self._prev = set(_children)
        self._op = _op
        self.label = label

    def __repr__(self):
        return f"Value(data={self.data})"

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), '+')

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), '*')

    def tanh(self):
        x = self.data
        t = (math.exp(2*x) - 1) / (math.exp(2*x) + 1)
        return Value(t, (self,), 'tanh')

Exercise 4 · move 4

One node or many

Compute tanh once as a single formula and once from smaller pieces (an exp, additions, a multiplication and a power of −1). Then check that 1 − tanh² matches a nudged slope at three points.

One way to write it 
import math

def tanh_one_op(x):                        # one node, as the lecture writes it
    return (math.exp(2*x) - 1) / (math.exp(2*x) + 1)

def tanh_atoms(x):                         # the same thing from smaller pieces
    e = math.exp(2 * x)
    top = e + (-1.0)
    bottom = e + 1.0
    return top * bottom**-1

for x in [0.0, 0.8813735870195432, 2.0]:
    print(f"x = {x:.4f}: one op {tanh_one_op(x):.6f}, from atoms {tanh_atoms(x):.6f}")

# the local derivative is all a node needs: check 1 - tanh^2 against nudging
h = 1e-6
for x in [0.0, 0.8813735870195432, 2.0]:
    t = math.tanh(x)
    nudged = (math.tanh(x + h) - t) / h
    print(f"x = {x:.4f}: 1 - tanh^2 = {1 - t*t:.6f}, nudged {nudged:.6f}")
x = 0.0000: one op 0.000000, from atoms 0.000000
x = 0.8814: one op 0.707107, from atoms 0.707107
x = 2.0000: one op 0.964028, from atoms 0.964028
x = 0.0000: 1 - tanh^2 = 1.000000, nudged 1.000000
x = 0.8814: 1 - tanh^2 = 0.500000, nudged 0.500000
x = 2.0000: 1 - tanh^2 = 0.070651, nudged 0.070651

The pieces give the same value as the single node. In micrograd, the many-piece version would need local derivatives for exp, plus, times and powers, while the one-node version needs just one — that is the trade-off of move 4.

Exercise 5 · moves 2 and 6

Saturation

Print tanh(n) and its local derivative 1 − tanh²(n) for n from 0 to 8. What happens to the gradient that can flow back through a neuron whose sum is large?

import math

print(" n      o = tanh(n)   do/dn = 1 - o^2")

By n = 4 the neuron passes back about a thousandth of the gradient, and by n = 8 practically nothing: a saturated neuron barely learns. It is one reason large weights and biases at the start of training can stall it.

Exercise 6 · moves 9–12

Count the cost

Write a toy loss with N weights that counts how often it runs, and compute its gradient by nudging for N = 3, 10 and 1,000. How many forward passes does each gradient take?

One way to write it 
import math
import random

calls = 0
def loss(weights, xs):
    """A toy model: one tanh neuron per weight, summed. Counts how often it runs."""
    global calls
    calls += 1
    return sum(math.tanh(w * x) for w, x in zip(weights, xs)) ** 2

def grad_by_nudging(weights, xs, h=1e-6):
    base = loss(weights, xs)
    g = []
    for i in range(len(weights)):
        bumped = list(weights); bumped[i] += h
        g.append((loss(bumped, xs) - base) / h)
    return g

random.seed(0)
for n in [3, 10, 1000]:
    ws = [random.uniform(-1, 1) for _ in range(n)]
    xs = [random.uniform(-1, 1) for _ in range(n)]
    calls = 0
    grad_by_nudging(ws, xs)
    print(f"{n:5d} weights: {calls:5d} forward passes for one gradient by nudging")
print("backprop: 1 forward pass + 1 backward pass, whatever the number of weights")
    3 weights:     4 forward passes for one gradient by nudging
   10 weights:    11 forward passes for one gradient by nudging
 1000 weights:  1001 forward passes for one gradient by nudging
backprop: 1 forward pass + 1 backward pass, whatever the number of weights

N + 1, every time: the cost grows with the model. Backprop’s does not — which is the whole of move 10 in one printout.

Sixteen questions: tap an answer to see the reason. Your first tap on each question is the one that counts.

1. In the model of a neuron, how does a synapse combine with its input?

What flows to the cell body is w times x, one per input (move 2).

2. What does the bias do?

It is added to the sum before the activation function (move 2).

3. tanh squashes its input into which range?

0 at 0, capped smoothly at 1 and −1 (move 2).

4. Why can tanh be a single node in micrograd?

Functions can be at any level of abstraction, as long as you can differentiate through them (move 4).

5. Why set the bias to 6.8813…?

Chosen so the backward pass works out to halves (moves 4 and 6).

6. o = tanh(n). What is do/dn?

The derivative of tanh is 1 − tanh², and tanh(n) is o (move 6).

7. n.grad is 0.5. What is b.grad?

A plus node distributes the gradient unchanged (move 7).

8. Why is w2.grad zero?

The times node’s local derivative for w2 is x2, which is 0 (move 8).

9. w1.grad is 1. To raise the neuron’s output, w1 should…

A positive gradient means increasing the weight increases the output, proportionally (move 8).

10. Which derivatives does training actually use?

The weights are what the optimiser changes (moves 5 and 9).

11. Getting a gradient by nudging, for a network with N weights, takes about…

One base pass, then one per nudged weight (move 10).

12. And by backpropagation?

One forward and one backward pass give every slope (moves 10 and 12).

13. The credit assignment problem asks…

Hidden units have no targets of their own; backprop hands each its share through the chain rule (move 11).

14. Why does backprop run backwards rather than forwards?

Forward mode needs a sweep per input; reverse mode a sweep per output (move 12).

15. What does “deep” mean in deep learning?

Depth is the number of layers stacked on each other (move 13).

16. In the book’s network, what is ∂ℓ/∂βk?

The bias adds straight in, like the neuron’s b (moves 7 and 14).

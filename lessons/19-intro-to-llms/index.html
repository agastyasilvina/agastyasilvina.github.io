Study notes · Topic 19 · Intro to large language models, part 1

Two files — and a lossy zip of the internet.

A large language model is a 140-gigabyte file of numbers and about five hundred lines of code to run them. Getting the numbers is the hard part: you squeeze ten terabytes of the internet into them by teaching a network to predict the next word, and what comes out can dream web pages. Then you fine-tune it on a hundred thousand good conversations, and it becomes an assistant. This is the first part of Andrej Karpathy’s talk, followed section by section in its own order, with what’s changed since late 2023 boxed alongside.

The talk was posted in November 2023, a re-recording of one Karpathy had just given at an AI security summit run by Scale AI — hence the Scale AI jokes. Its first part, covered here, answers three questions: what a large language model is, how one is trained, and how a text predictor becomes a chatbot. The notes keep to the talk’s order, one move per section, and the talk’s own content is the main text. Beyond the lecture boxes add newer facts and the mechanisms the talk skips; a lot has moved since 2023, so they matter more than usual here. Watch for boxes flag the few places where the talk slips or has dated. Two labs let you size a model file and run a tiny next-word machine of your own.

Arc A · What an LLM is

2 moves
1

Two files

What a large language model physically is

The talk’s opening answer: a large language model is just two files. Its example is Llama 2 70B, released by Meta AI — the second generation of the Llama series, and the 70-billion-parameter member of it. The series comes in 7, 13, 34 and 70 billion parameters, and 70B is the biggest.

People like this model, Karpathy says, because it’s probably the most powerful open-weights model of the day: Meta released the weights, the architecture and a paper, so anyone can work with it. That’s unlike ChatGPT, whose architecture was never released. OpenAI owns it; you can use it through a web page, but you never have the model itself.

So Llama 2 70B is two files on your disk:

  • The parameters file — the weights of the neural network. There are 70 billion of them, each stored as a 16-bit floating-point number, which takes two bytes. 70 billion × 2 bytes = 140 gigabytes.
  • The run file — the code that runs the network using those parameters. It could be written in any language; in C, about 500 lines, with no other dependencies.

That’s the whole package. Put the two files on a MacBook, compile the C, point the program at the parameters, and you can talk to the model — no internet connection, nothing else needed.

Try it — how big is the parameters file?

140 GB parameters file

Beyond the lectureThe talk’s “run” file is real: Karpathy published llama2.c in July 2023, one dependency-free C file — about 700 lines, by its own description — that runs Llama-style models. Two things have since changed what running one on a laptop means. Quantisation — storing each parameter in 4 bits instead of 16 — shrinks a 70B model from 140 GB to about 35 GB on paper (try it above) and about 40 GB as real files, small enough for a 64 GB laptop; programs such as llama.cpp, from 2023, made this routine.

And “open weights” isn’t quite open source. Llama 2’s licence let anyone use the weights, but required companies with more than 700 million monthly users to ask Meta’s permission, and the training data was never released — so the Open Source Initiative doesn’t count it as open source. Meta itself has since wavered: its 2026 flagship, Muse Spark, is proprietary, though it released a smaller open-weight model, Muse Glimmer, that August.

Watch forLlama 2 had four sizes on paper but only three in the release. Meta trained a 34-billion-parameter model and reported it in the paper, but held it back, saying it hadn’t had time to test its safety thoroughly enough. The family people could download was 7B, 13B and 70B.

2

Running it

Inference: cheap to run, expensive to make

The talk demonstrates by sending the model a request — write a poem about the company Scale AI — and the model starts generating, following the instruction and producing a poem. Karpathy explains the running joke: the event where the talk was first given was run by Scale AI, so the slides “pick on” the company throughout to keep things concrete.

Then a small confession: the demo video wasn’t the 70-billion-parameter model but the 7-billion one, because the 70B would run about ten times slower. The point stands, though. Running a model — inference — needs very little: a small package and a laptop. Everything in the run file, the architecture and its “forward pass”, is understood and open. The magic is in the parameters, and getting them — training — is a far more involved, computationally heavy process.

Beyond the lectureWhy is ten times the parameters about ten times slower? To produce each new word, the computer has to read every one of the parameters from memory once. For a laptop, the limit is usually how fast memory can be read, not how fast it can do arithmetic, so a file ten times bigger takes roughly ten times longer per word. It’s also why shrinking the numbers (the lab above) speeds models up as well as fitting them in.

Compressing the internet

Training: 10 TB, 6,000 GPUs, 12 days, $2 million

Training, the talk says, is best understood as compressing a good chunk of the internet. Because Llama 2 is open, Meta’s paper tells us roughly what was involved:

~10 TBof text, from a crawl of the internet
~6,000GPUs in a cluster
~12 daysof training
~$2Mto get Llama 2 70B

The text comes from crawling websites of every kind and collecting it together. The GPUs are specialised computers built for very heavy workloads like training neural networks. What comes out is the 140 GB parameters file, which you can think of as a zip file of the internet, roughly a hundred times smaller than the text that went in.

But it isn’t really a zip file. A zip file is lossless: you get the identical text back. This is lossy compression: the parameters hold a kind of gestalt of the text, not a copy of it.

And these, Karpathy adds, are “rookie numbers” by the standards of the day. For the state-of-the-art models behind ChatGPT, Claude or Bard, multiply them by ten or more. That’s why training runs already cost tens or even hundreds of millions of dollars, with very large clusters and very large datasets. Once you have the parameters, though, running the network is cheap.

Beyond the lectureMeta’s paper reports tokens and GPU-hours rather than terabytes and dollars, so the talk’s round numbers are conversions — and they check out. Llama 2 was trained on 2 trillion tokens, and the 70B model took about 1.7 million GPU-hours on Nvidia A100 chips. Spread over 6,000 GPUs that’s about 12 days, and at roughly a dollar per GPU-hour about $2 million. Ten terabytes divided by 140 gigabytes is about 70, so “roughly 100×” is generous.

The rookie numbers have kept climbing. Meta trained Llama 3 (2024) on over 15 trillion tokens, and Llama 3.1 405B on about 16,000 H100 GPUs. Sam Altman said GPT-4 cost more than $100 million to train, and the Stanford AI Index estimated Google’s Gemini Ultra at about $191 million in computing alone. Epoch AI estimates that the cost of frontier training runs has grown about 2.4 times a year since 2016, and put xAI’s Grok 4 (2025) at about $490 million. As of October 2026 the largest AI data centre, xAI’s Colossus 2, has computing power equal to about 1.1 million H100s — nearly two hundred times the talk’s 6,000 GPUs. (Bard, one of the talk’s examples, was renamed Gemini in February 2024.)

4

Predicting the next word

The one task the network is trained to do

So what does the network actually do? It tries to predict the next word in a sequence. Feed it the words cat sat on a; inside, the parameters are spread through a network of connected neurons that “fire in a certain way”, and out comes a prediction for the next word — say, mat, with 97% probability. That’s fundamentally the whole problem it solves.

This is also why the talk calls training compression. There’s a close mathematical link between prediction and compression: if you can predict the next word very accurately, you can use that to compress the dataset. A next-word predictor is, in a precise sense, a compressor of the text it learned from.

Beyond the lectureTwo refinements. First, models don’t really see words but tokens — common words, pieces of words and punctuation, from a fixed vocabulary. The talk says “word” to keep things simple, and so do these notes. Second, the prediction–compression link is concrete. A compressor needs to spend fewer bits on likely things and more on surprising ones; give it a good predictor and it can encode text in fewer bits than any general-purpose zip program, a technique called arithmetic coding that goes back to Claude Shannon’s information theory.

How good a compressor? DeepMind’s 2023 paper “Language Modeling Is Compression” found that its Chinchilla 70B model, trained mainly on text, squeezed image patches to under half their size and audio to about a fifth — beating PNG and FLAC, formats designed for exactly those jobs. The catch: those figures don’t count the size of the model itself, which dwarfs the data. (For scale: in English a token averages about three-quarters of a word, and Llama 2’s vocabulary has 32,000 tokens.)

Drill — be the network

Fill each blank, and notice what you had to know: “The capital of Australia is ___.” “Water boils at 100 degrees ___.” “Twinkle, twinkle, little ___.” Each blank is easy only if you’ve absorbed a fact or a pattern. The lab in move 6 shows a tiny machine making the same kind of guess.

5

Prediction teaches the world

The Ruth Handler page

Why is the result such a “magical artifact”? Next-word prediction sounds like a simple objective, but it’s a powerful one, because doing it well forces the network to learn a lot about the world.

The talk’s example is a random Wikipedia page from the day the slides were made, about Ruth Handler. Imagine being the network, reading the page word by word and trying to predict each next word. Karpathy highlights in red the words that carry the most information — names, dates, what Handler did. To predict those, the parameters have to know them: who Ruth Handler was, when Handler was born and died, what Handler achieved. Across the whole internet, the task of next-word prediction packs an enormous amount of knowledge into the weights.

Beyond the lectureRuth Handler co-founded the toy company Mattel and created the Barbie doll, launched in 1959; Handler was born in 1916 and died in 2002. The bigger idea has a history too. OpenAI’s GPT-2 paper (2019) showed that a model trained only to predict the next word could already translate, summarise and answer questions roughly, without being taught any of them — the first strong sign that prediction alone builds broad knowledge and skill.

Drill — the red words

Take any short article and underline every word you could only predict if you already knew a fact — names, numbers, dates, causes. Those are the words that force a model to store knowledge. The rest (“the”, “was”, “in”) it gets from grammar alone.

6

Dreaming documents

Sampling, and why it hallucinates

Once trained, the network is used in a simple loop: predict the next word, sample one — pick a word according to the predicted probabilities — feed it back in, predict again, and keep going. Run that and the network “dreams” internet documents: it was trained on web pages, so let loose, it produces web-page dreams. The talk shows three:

  • Java code — something that looks like a real program.
  • An Amazon product listing — title, author, ISBN number, the lot, all made up. The ISBN almost certainly doesn’t exist: the network has simply learned that after “ISBN:” comes a number of about that length, and puts in whatever looks reasonable. It’s parroting the distribution of its training data.
  • A Wikipedia-style article about the blacknose dace, which turns out to be a real fish. This text doesn’t appear word for word anywhere in the training data, yet what it says about the fish is roughly correct. The network has knowledge of the fish without copying any document about it.

That is lossy compression in action: the network remembers the gestalt, produces the right form, and fills it with what it knows. And you can never be 100% sure whether a given output is a hallucination — an incorrect answer — or correct. Some of it may be memorised and some not, and you don’t know which is which. Mostly, it is dreaming text from the distribution it learned.

Beyond the lectureThe fish is real: the blacknose dace is a small minnow of clear, fast streams in eastern North America. Temperature, the lab’s slider, is the dial on sampling: near zero the model always takes the likeliest word; higher, it takes more chances, which makes text more varied and more often wrong. Memorisation is real too: models occasionally reproduce long passages of their training text word for word, which researchers have extracted on purpose, and which sits behind copyright cases such as The New York Times’s suit against OpenAI (December 2023).

On why hallucination persists, OpenAI argued in September 2025 that training and benchmarks reward confident guessing over admitting uncertainty — the way a multiple-choice exam rewards a guess over a blank.

Drill — catch it hallucinating

Start from “Ada Quill was” or “title:” and dream a few times. Then check the result against the machine’s reading in the box. You’ll get sentences in exactly the right form — a birth year, a founding, a book with an author and a page count — with the facts quietly swapped between people and books. That’s the ISBN in the talk’s Amazon dream, at toy scale.

How does it work?

A transformer we can build but can’t read

“This is where things complicate a little bit.” The network is a transformer, and the remarkable thing is that we understand its architecture in full detail: we know exactly what mathematical operation happens at every stage. The problem is that the hundred-billion-odd parameters are spread throughout it. All we know is how to adjust them, step by step, so that the whole network gets better at predicting the next word. We can measure that it’s improving. We don’t know how the parameters collaborate to do it.

We have rough, high-level models of what’s going on — the network seems to build and maintain a kind of knowledge database — but even that database is strange and imperfect. The talk’s example is the viral reversal curse. Ask GPT-4, the best model of the day, who is Tom Cruise’s mother? and it says Mary Lee Pfeiffer, correctly. Ask who is Mary Lee Pfeiffer’s son? and it says it doesn’t know. The knowledge is “one-dimensional”: not stored so it can be reached from every direction, but only from the direction it was learned in.

So think of large language models as mostly inscrutable artifacts. They’re unlike anything else in engineering — not like a car, where we understand every part — because they come out of a long optimisation process. A field called interpretability, or mechanistic interpretability, tries to work out what each part does, and can partly, but not fully. For now they’re treated mostly as empirical artifacts: give them inputs, measure the outputs, study their behaviour in many situations. That’s why working with them needs correspondingly sophisticated evaluations.

Beyond the lectureThe transformer comes from a 2017 Google paper, “Attention Is All You Need”. Its key step, attention, lets every word look back at all the earlier words and weigh which ones matter for the next prediction. The “adjusting” the talk mentions is gradient descent: after each prediction, every parameter is nudged slightly in whichever direction would have made the right word more likely.

Interpretability has moved since 2023. Anthropic’s “Scaling Monosemanticity” (May 2024) found millions of human-readable “features” inside a production model — one for the Golden Gate Bridge which, turned up, made the model talk about the bridge constantly (“Golden Gate Claude”) — and its 2025 attribution-graph work traced some of the internal steps a model takes to reach an answer. MIT Technology Review named mechanistic interpretability one of its ten breakthrough technologies of 2026 — but nobody can yet read a whole model. The reversal curse comes from a September 2023 paper by Lukas Berglund and colleagues: GPT-4 named celebrities’ parents correctly about 79% of the time, but named the celebrities from their parents only 33% of the time.

Drill — ask it backwards

Ask a chatbot a fact in one direction and then in reverse: “Who wrote Pride and Prejudice?” and “Which famous novel did Jane Austen publish in 1813?” Then try something more obscure, where the reverse direction is rare on the web. The obscure pairs are where the curse still shows.

Fine-tuning into an assistant

Same training, different documents

Everything so far produces an internet document generator. That’s the first stage of training, called pre-training. But a document generator isn’t much use for most tasks; we want to ask questions and get answers. So there’s a second stage, fine-tuning, which produces an assistant model.

The method is surprisingly simple: keep the training identical — still next-word prediction — and swap the dataset. Instead of internet documents, train on documents collected by hand. Companies hire people, give them labelling instructions, and ask them to write questions and then the ideal answers. One training example might be a user asking for a short introduction to the term monopsony in economics, followed by the answer a person wrote, shaped by the labelling documentation that engineers at a company like OpenAI or Anthropic produce.

The two stages want different data:

Pre-trainingFine-tuning
DataInternet text, tens or hundreds of terabytesConversations written by people, e.g. 100,000
PriorityQuantity — and much of it is low qualityQuality over quantity
What it givesKnowledge“Alignment”: the format of a helpful assistant

After fine-tuning, the model “subscribes to the form” of its new training documents. Ask it something it never saw — can you help me with this code? It seems like there’s a bug, with a line printing “hello world” — and it answers in the style of a helpful assistant, sampling word by word as before. Karpathy calls this remarkable, empirical and not fully understood: the model changes its formatting to that of an assistant, yet can still reach and use all the knowledge it built up in pre-training.

Beyond the lectureReal datasets are smaller than the talk’s 100,000. OpenAI’s InstructGPT (2022) used about 13,000 written demonstrations; Meta stopped at 27,540 for Llama 2-Chat, under the heading “quality is all you need”; and the LIMA paper (2023) got a capable assistant from just 1,000 carefully chosen examples. LIMA called this the superficial alignment hypothesis — nearly all knowledge comes from pre-training, and fine-tuning mostly teaches the format — which is the talk’s knowledge-versus-alignment split in a single phrase.

Mechanically, each conversation is written out as one document with special markers for who is speaking, so ordinary next-word training can learn to answer in the assistant’s turn.

How to train your ChatGPT

The talk’s summary: two stages, two clocks

The talk then sums up the recipe on a single slide:

Talking it through, Karpathy adds the reasons behind each clock. Pre-training needs a GPU cluster — special-purpose machines for parallel workloads, not something you can pick up at Best Buy — and costs a few million dollars, so it happens inside companies perhaps once a year or every several months. Fine-tuning is far cheaper: a day or so instead of months. Companies like Scale AI work with you to produce the documents your instructions describe.

The loop at the end is how assistants improve. When the deployed model misbehaves, you take the conversation where it went wrong and ask a person to overwrite the bad response with the correct one. That conversation goes into the training data, and next time you fine-tune, the model does better in that situation. Because fine-tuning is cheap, this can happen every week or even every day, and companies iterate much faster on it than on pre-training.

One more point: Meta released both kinds of Llama 2 model. The base model isn’t directly usable — ask it a question and it may give you more questions, because it’s only an internet document sampler. Its value is that Meta has done the very expensive stage 1 for you, so you can do your own fine-tuning, which gives you a lot of freedom. And for anyone who just wants to ask questions, Meta released the assistant models too.

Beyond the lectureScale AI, the talk’s running joke, became a big story in June 2025: Meta invested about $14.3 billion for 49% of the company and hired its chief executive, Alexandr Wang, to lead a new “superintelligence” lab, and several of Scale’s other large customers pulled back. Google, OpenAI and others wound down their work with Scale, which cut 14% of its staff that July.

The slide’s recipe has also grown. Since OpenAI’s o1 (September 2024) and DeepSeek-R1 (January 2025), leading models get a long reinforcement-learning stage after fine-tuning, practising on problems whose answers can be checked automatically, such as maths and code. Karpathy wrote in December 2025 that this “reinforcement learning from verifiable rewards” had become “the de facto new major stage”, so training is now usually described in three steps: pre-training, supervised fine-tuning, and reinforcement learning.

Drill — which stage fixes it?

For each problem, say which stage you’d go back to: (a) the assistant answers rudely; (b) it knows nothing about a field that barely exists online; (c) it formats code badly; (d) it doesn’t know about events after its training data was collected.

Answers

(a) Fine-tuning: write better example responses — cheap, this week. (b) Pre-training: knowledge comes from the big text stage, so it needs more of that text — expensive. (c) Fine-tuning. (d) Neither cheaply: it needs new pre-training data, or tools such as web search (which the talk’s later parts cover).

Comparisons and RLHF

An optional stage 3: judging is easier than writing

The slide’s stage 2 says “and/or comparisons”, and the talk “double-clicks” on that, because there’s an optional stage 3 that uses comparison labels.

The reason: for a human labeller, it’s often much easier to compare candidate answers than to write one. Suppose the task is write a haiku about paperclips. Many people couldn’t write a good haiku. But show them several haikus generated by the stage-2 assistant, and they can easily pick the best. Stage 3 uses those comparisons to fine-tune the model further. Karpathy skips the mathematics; at OpenAI the process is called reinforcement learning from human feedback, or RLHF, and it gives these models extra performance.

Beyond the lectureRLHF predates ChatGPT: Paul Christiano and colleagues showed in 2017 how to train from human comparisons. The usual recipe has two steps. First, train a separate reward model to predict which of two answers people prefer. Then use reinforcement learning to push the assistant towards answers the reward model scores highly, on a leash that stops it drifting too far from its fine-tuned self. It pays: in the InstructGPT paper, people preferred a 1.3-billion-parameter RLHF model to the original 175-billion-parameter GPT-3. And it takes a lot of judging — Meta collected about 1.4 million comparisons for Llama 2-Chat.

Newer methods trim the recipe. DPO (2023) learns from the comparisons directly, with no reward model — Zephyr 7B Beta, on the talk’s leaderboard, was an early well-known example — and the reasoning models of 2024–25 learn from answers that can be checked automatically instead of from human judgement.

Drill — feel the difference

Time yourself writing a haiku about paperclips. Then ask a chatbot for three and time yourself choosing the best. The gap between the two times is the whole economic case for comparison labels.

11

Who writes the labels

Helpful, truthful, harmless — and a slider

A glimpse of real labelling instructions: an excerpt from OpenAI’s InstructGPT paper, asking labellers to make responses helpful, truthful and harmless. Real labelling documents can grow to tens or hundreds of pages and get complicated, but that is roughly what they look like.

Then a correction to the picture so far. The process has been described as humans doing all the work, and that’s “not exactly right”, and growing less right. The models themselves keep getting better, so labels are increasingly made by human–machine collaboration:

  • models sample answers, and people cherry-pick the best parts into one single best answer;
  • models check a labeller’s work;
  • models create the comparisons, with people in an oversight role.

Think of it as a slider between all-human and all-machine labelling. As the models improve, the slider keeps moving towards the machine.

Beyond the lectureInstructGPT’s labels came from about 40 contractors, hired through Upwork and — fittingly, given the talk’s running joke — Scale AI. The slider has moved a long way since. Anthropic’s Constitutional AI (December 2022) has the model critique and revise its own answers against a written list of principles, and replaces many human comparisons with AI-generated ones (“RLAIF”). Synthetic data — examples written by other models — is now a large part of how assistants are trained. And companies have begun publishing their rulebooks, such as OpenAI’s Model Spec (2024).

The leaderboard

Chatbot Arena, and the gap between closed and open models

Part one closes with a leaderboard: Chatbot Arena, run by a team at Berkeley. It ranks models by Elo rating, calculated much as in chess, where players’ ratings come from their results against each other. On the website you type a question, get answers from two anonymous models, and pick the winner; the wins and losses add up to ratings. Higher is better.

What it showed in late 2023:

  • At the top, proprietary models — closed, no access to the weights, usually used through a web page: the GPT series from OpenAI, the Claude series from Anthropic, and a few from other companies. The best performers.
  • Just below, open-weights models — weights available, much more known about them, usually with a paper: Meta’s Llama 2 series, and further down Zephyr 7B Beta, built on the Mistral series from a French start-up.

The dynamic, as Karpathy describes it: closed models work much better, but you can’t download them, fine-tune them or really work with them — only use them through a web interface. The open ecosystem works worse but may be good enough for your application, and it’s trying to boost performance and chase the proprietary models.

That is where the recording ends, at the close of the talk’s first part. Its later parts turn to the future of language models and to their security.

Beyond the lectureThe Elo arithmetic: a 100-point gap means the stronger model wins about 64% of head-to-heads; 200 points, about 76%; 400 points, about 91%.

The arena itself has changed. It replaced online Elo with the closely related Bradley–Terry model in December 2023, became a company, LMArena, in 2025, and renamed itself simply Arena in January 2026. It has drawn criticism too. An April 2025 paper, “The Leaderboard Illusion”, found that large providers tested many private variants and published only the best — Meta tried 27 before Llama 4 — and that same month Meta was criticised for advertising the arena score of an unreleased “experimental” Llama 4 tuned for chatting; the model it actually released ranked 32nd. Votes measure which answer people prefer, style and length included, not only which is right. As of 2 October 2026, its text leaderboard was led by Google’s Gemini 4 and a run of Anthropic’s Claude models, with OpenAI’s best in 20th place.

And the gap the talk describes has narrowed sharply. DeepSeek-R1 (January 2025, released under the permissive MIT licence) matched OpenAI’s o1 on many tests, and OpenAI itself released open-weight models, gpt-oss, in August 2025. Epoch AI put the lag of the best open models behind the best closed ones at about a year in late 2024 and about four months by mid-2026. The strongest open models now come mostly from Chinese labs — Moonshot’s Kimi (the top open model on the arena, 16th), Z.ai’s GLM, DeepSeek, and Alibaba’s Qwen, which has become the community’s most common base model. Zephyr itself came from Hugging Face, built on Mistral 7B; Mistral AI was founded in Paris in April 2023.

Watch for“Elo” isn’t an acronym, though it’s often written ELO: it’s named after Arpad Elo, the physicist who devised the chess rating system. And treat the late-2023 leaderboard as a snapshot — the order has turned over many times since.

Under the hood

What micrograd is, and why backpropagation matters

The lecture opens with a promise: start from a blank Jupyter notebook and, by the end, define and train a neural network, seeing everything that goes on under the hood and how it works at an intuitive level.

The route is to build micrograd, a library Karpathy had put on GitHub about two years earlier. At the time only the source code went up, so you had to study it yourself to see how it worked. The lecture builds it step by step instead, coming up with every piece as it goes.

So what is micrograd, and why is it interesting? It’s an autograd engine — autograd is short for automatic gradient — and what it really does is implement backpropagation. Backpropagation is an algorithm that efficiently evaluates the gradient of a loss function with respect to the weights of a neural network. That is what lets you tune the weights over and over, making the loss smaller and so the network more accurate. It is why backpropagation sits at the mathematical core of every modern deep-learning library, such as PyTorch or JAX.

In three linesweights → network → loss (one number: how wrong it is) backpropagation → how the loss changes with each weight nudge every weight a little downhill → repeat

Beyond the lecturemicrograd went up on GitHub in April 2020, and the lecture was posted on 16 August 2022 as the first video of Karpathy’s course Neural Networks: Zero to Hero. Both micrograd and the course notebooks are MIT-licensed, which is why short snippets of them appear on this page.

In the libraries the lecture names, the same idea looks like this: PyTorch records the operations as you compute a loss, and loss.backward() fills in a .grad for every parameter (PyTorch autograd); in JAX, jax.grad(f) hands you a new function that returns the gradient of f (JAX autodiff).

The algorithm is older than deep learning. Its general form, reverse-mode automatic differentiation, was first published by Seppo Linnainmaa in a 1970 master’s thesis. Paul Werbos described training neural networks this way in a 1974 PhD thesis and applied it to multi-layer networks in the now-standard way in 1982, and Rumelhart, Hinton and Williams’s 1986 paper in Nature, “Learning representations by back-propagating errors”, made it the way networks are trained.

Elsewhere in these notesTopic 19’s “parameters file” (move 1) is 70 billion of these weights, and the “adjusting” it mentions in move 7 is gradient descent. This series is where that machinery starts, one number at a time.

An expression that remembers

micrograd’s own example: a forward pass, a backward pass, and a.grad = 138

To show what micrograd does, the lecture scrolls to the example in its README. There are two inputs, a = −4 and b = 2, but each number is wrapped in a value object — the object the lecture is about to build, and the subject of part 2. From a and b the code builds c, d, e, f and finally g, showing off the operations micrograd supports: adding and multiplying values, raising to a constant power, adding a constant, negating, squashing at zero (the ReLU), dividing by a constant, dividing by another value.

While that code runs, micrograd quietly builds the whole expression graph. It knows that c is a value too, that c came from an addition, and that c’s children are a and b, because it keeps pointers to those two value objects. So it knows exactly how everything is laid out.

Two things can then happen. The forward pass computes the output: read g.data and you get 24.7041. The big deal is the backward pass. Call g.backward(), and backpropagation starts at g, works backwards through the graph, and applies the chain rule from calculus recursively. That gives the derivative of g with respect to every internal node — e, d and c — and with respect to the inputs. Ask for them: a.grad is 138.8338 and b.grad is 645.5773.

Those derivatives are the important information, because they say how a and b affect g through the expression. a.grad = 138 means: nudge a up by a tiny amount and g grows, with slope 138 — g rises by about 138 times the size of the nudge. The slope for b is 645. Together they say how g responds if a or b is tweaked a little in the positive direction.

The expression itself, the lecture adds, is completely meaningless: it was made up to show what micrograd can do.

from micrograd.engine import Value

a = Value(-4.0)
b = Value(2.0)
# … eight lines build c, d, e, f from a and b …
g = f / 2.0
g += 10.0 / f
print(f'{g.data:.4f}')  # 24.7041: the forward pass
g.backward()
print(f'{a.grad:.4f}')  # 138.8338: dg/da
print(f'{b.grad:.4f}')  # 645.5773: dg/db

Adapted from micrograd’s README, by Andrej Karpathy (MIT licence). The full expression is in Build it, exercise 3.

Beyond the lectureYou can check those numbers today without micrograd. Write the README’s expression as an ordinary Python function and nudge each input by a millionth: you get 138.8338 and 645.5773 (Build it, exercise 3). That slow route — nudge and measure — is exactly what arcs B and C teach. Backpropagation gets the same numbers without any nudging, which is what makes it fast.

Watch fora.grad isn’t a property of a on its own. It is ∂g/∂a, the derivative of the final output with respect to a, so it is a fact about everything downstream of a. Change any later line of the expression and a.grad changes, though a hasn’t.

3

Just mathematical expressions

Why the machinery fits neural networks — and why it’s bigger than them

You might wonder what that expression was for. It doesn’t matter; what we really care about is neural networks. And neural networks turn out to be just mathematical expressions like that one — “a bit less crazy, even”.

A neural network is an expression that takes two kinds of input: the input data and the weights of the network. Its output is the network’s predictions or, one step further, the loss function. So neural networks are simply a certain class of mathematical expressions.

Backpropagation, though, is significantly more general. It doesn’t care about neural networks at all, only about arbitrary mathematical expressions. We happen to use that machinery to train neural networks.

Lecture ↔ bookPrince puts it the same way: a supervised model is “just a mathematical function” (section 2.1, move 14), and even a two-hidden-layer network, written out in full, is still only an equation relating input to output (section 4.3, move 22).

4

Scalars, not tensors

Why micrograd works one number at a time

One more note before building: micrograd is a scalar-valued autograd engine. It works at the level of individual numbers like −4 and 2, and breaks neural networks down all the way to those atoms — single scalars, and every little plus and times.

That is excessive, and you would never do it in production. It is done for teaching: it spares you the n-dimensional tensors that modern deep-learning libraries use, so that you understand backpropagation, the chain rule and neural-network training at the fundamental level.

To train bigger networks you do need tensors, but none of the math changes. A tensor is just an array of these scalars, packaged up. Operating on whole arrays at once lets the computer take advantage of its parallelism — all those operations can run at the same time — so the whole thing runs faster. It is purely for efficiency. That is why Karpathy doesn’t think tensors are useful when learning from scratch, and why micrograd exists: understand how things work at the fundamental level, then speed it up later.

Beyond the lectureA tensor is an n-dimensional array: a single number has no dimensions, a list has one, a table two, and a batch of colour photos four (photo × height × width × colour channel). The arithmetic inside is identical; what changes is who runs the loop. A Python loop handles one number per step, while NumPy or PyTorch hands the whole array to compiled code or a graphics card that does thousands of the same operation at once.

Lecture ↔ bookPrince’s matrix notation (section 4.4, move 23) is the tensor view. One matrix–vector product, Ωh, stands for a whole layer’s worth of the multiplications and additions that micrograd will do one scalar at a time.

A hundred lines

engine.py and nn.py: everything else is efficiency

Now the fun part. Karpathy’s claim is that micrograd is all you need to train neural networks, and everything else is just efficiency. You might expect it to be a complex piece of code. It isn’t.

The micrograd repository has two files. engine.py is the actual engine — backpropagation and autograd — and it knows nothing about neural networks. It is about a hundred lines of very simple Python, which the lecture promises you’ll understand by its end. nn.py is the neural-network library built on top, and Karpathy calls it “like a joke”: define what a neuron is, then a layer of neurons, then a multi-layer perceptron, which is just a sequence of layers.

That’s about 150 lines in all, and it is all you need to understand to understand neural-network training. There is a lot to efficiency, of course, but fundamentally that is all that’s happening.

Then the lecture dives in — and its first step isn’t code but an idea: a very good intuitive understanding of what a derivative is, and exactly what information it gives you.

Beyond the lectureAs of October 2026, micrograd’s engine.py has 94 lines and nn.py has 60, blank lines included — so “about 150” is about right. Build it (≡) lays out the road from this page to your own copy of both files.

A function to play with

f(x) = 3x² − 4x + 5, and why nobody differentiates a network by hand

The notebook starts with the imports Karpathy pastes into every notebook — math, numpy and matplotlib — and a scalar-valued function made up for the occasion: f(x) = 3x² − 4x + 5. It takes a single scalar x and returns a single scalar y. Call it with 3.0 and you get 20 back.

To see its shape, plot it. From the formula you can tell it’s probably a parabola, since it’s a quadratic. Make a set of inputs with np.arange(-5, 5, 0.25) — from −5 up to, but not including, 5, in steps of 0.25 — and call f on that whole array: numpy applies the function to every element independently. Then plt.plot(xs, ys) draws a nice parabola. The earlier f(3.0) = 20 is the point at x = 3, height 20.

def f(x):
  return 3*x**2 - 4*x + 5

f(3.0)          # 20.0

ys = f(xs)

From the lecture notebook, nn-zero-to-hero (MIT licence).

Now the question that matters: what is the derivative of this function at any single input x?

In a calculus class you would take 3x² − 4x + 5, apply the product rule and the other rules on paper, derive the expression for the derivative, and plug in different values of x. The lecture deliberately doesn’t, because nobody in neural networks writes out the expression for the network: it would be massive, with tens of thousands of terms, and nobody derives its derivative symbolically. Instead, it goes back to the definition of the derivative, to make sure we really understand what it measures and what it tells us about the function.

Beyond the lectureThere are three ways to get a derivative. Symbolic: the calculus-class rules, which give a formula — exact, but the formulas blow up for big expressions. Numerical: nudge and measure, as in the next move — easy, but approximate, and it needs one extra evaluation per input. Automatic: what micrograd does. It never writes down a formula for the derivative; it applies the exact rule for each small operation to the numbers flowing through and chains them together, so it is exact like the symbolic route and mechanical like the numerical one. Baydin and colleagues’ survey “Automatic differentiation in machine learning” (2018) sets the three side by side.

Rise over run

The definition of a derivative, measured at x = 3

Look up “derivative” online, Karpathy notes, and the first definition you find is really the definition of being differentiable — not much help. The one to remember from calculus is this:

f′(x) = limh→0 f(x + h) − f(x)h

In words: you are at some point x that you care about. Bump it up by a small number h. How does the function respond — with what sensitivity? Does it go up or down, and by how much? That response, per unit of bump, is the slope of the function at that point.

So the derivative can be estimated numerically. The definition asks for h to go all the way to zero; instead, just pick a very small h, say 0.001, at the point x = 3.0. There f(x) is 20. Now nudge x a little in the positive direction: do you expect f(x + h) to be slightly more than 20 or slightly less? At 3 the function is climbing, so slightly more. And by how much tells you the size of the slope.

f(x + h) − f(x) is how much the function responded — the rise. Normalise it by the run, h, and rise over run is the slope. It is only a numerical approximation, because h has to be made very small to converge on the exact value.

def f(x):
    return 3*x**2 - 4*x + 5

h = 0.001
x = 3.0
print((f(x + h) - f(x))/h)
14.00300000000243

A warning comes with it. Keep adding zeros to h and at some point the answer goes wrong, because computers use floating-point arithmetic: every number is stored in a finite amount of memory, and eventually that bites. With a sensible h you converge on the right answer: at 3, the slope is 14.

You can check that by differentiating 3x² − 4x + 5 in your head: 3x² becomes 6x, the −4x becomes −4, and the 5 disappears, so the derivative is 6x − 4. At x = 3 that’s 18 − 4 = 14. Correct.

Beyond the lectureHow small is too small? Python’s floats are, on almost every machine, IEEE 754 “double precision” numbers: 53 bits of precision, about 15–16 significant decimal digits (Python’s floating-point tutorial). The gap between neighbouring floats is 2−52 ≈ 2.2 × 10−16 at 1 — sys.float_info.epsilon — about 4.4 × 10−16 near 3, and 3.6 × 10−15 near 20.

Two things go wrong as h shrinks. First, 3 + h gets rounded, so the run actually used isn’t h. Second, f(x + h) − f(x) subtracts two numbers that agree in almost every digit, and their tiny rounding errors, around 10−15, are then divided by a tiny h. At h = 10−15 the estimate at x = 3 comes out as 10.66; at h = 10−16, 3 + h rounds back to exactly 3, the rise is zero, and the “slope” is 0.0.

Meanwhile the bend of the curve pushes the other way: for this parabola the estimate is too big by exactly 3h. The two errors balance near h ≈ √ε ≈ 10−8, the rule of thumb in the step-size section of Wikipedia’s “Numerical differentiation”; there the error at x = 3 is about 10−7. The lab in the next move draws the whole trade-off.

Watch forThe numerical slope is never exact. With h = 0.001 at x = 3 it says 14.003, and the extra 0.003 is that 3h: the parabola curving away from its tangent. Making h smaller improves it — until rounding takes over. Printing more decimal places never does.

Down, flat, up

The sign of the slope at x = −3, 2/3 and 3

Now try x = −3. Guessing the exact slope there is hard, but guessing its sign isn’t. At −3, if you nudge x a little in the positive direction, the function goes down, so the slope must be negative. f(−3) is 44, and the nudged value comes out slightly below 44. The numerical slope is about −22 — and 6 × (−3) − 4 = −22.

Somewhere in between, the slope must be zero. For this function, Karpathy had looked it up: it’s at x = 2/3. At that precise point, a nudge in the positive direction leaves the function almost exactly where it was. It doesn’t respond, and that is why the slope is zero.

f′(x) = 6x − 4 negative left of 2/3 (the curve falls) · zero at 2/3 (the bottom) · positive right of it (the curve climbs)

Three inputs, one output

d = a·b + c, and what happens when you nudge a

Next the lecture “complexifies” a little. Now there is an output d that is a function of three scalar inputs, a, b and c: d = a·b + c, with a = 2, b = −3 and c = 10 — three inputs into an expression graph, and a single output. Printing d gives 4.

Again the goal is the derivatives — of d with respect to a, to b and to c — and, again, the intuition for what each one tells us. The method is a bit hacky. Take a very small h, 0.0001. Fix the inputs at the values you care about: that is the point at which all three derivatives will be evaluated. Compute d1 from the expression. Then bump one input by h, compute d2 from exactly the same expression, and print the slope, (d2 − d1)/h: how much the function changed when you bumped that one input, normalised by h.

Before running it, think. d1 will be 4. If a is bumped, will d2 be slightly more than 4 or slightly less? That decides the sign of the derivative. a gets slightly more positive, but b is negative, so a·b gets more negative: we add less to d. You should expect d to go down.

h = 0.0001

# inputs
a = 2.0
b = -3.0
c = 10.0

d1 = a*b + c
a += h
d2 = a*b + c

print('d1', d1)
print('d2', d2)
print('slope', (d2 - d1)/h)
d1 4.0
d2 3.999699999999999
slope -3.000000000010772

From the lecture notebook, nn-zero-to-hero (MIT licence), with a as the input that’s bumped.

And it does: d went from 4 to 3.9997, so the slope is negative, and its exact value is −3. You can convince yourself that’s right with calculus: differentiate a·b + c with respect to a and you get just b — and b is −3.

10

One slope per input

∂d/∂b = a, ∂d/∂c = 1 — and where these notes leave the lecture

Now bump b instead, by a little in the positive direction, and you get a different slope. What is b’s influence on d? Because a is positive, a bigger b adds more to d. And the sensitivity — the slope of that addition — shouldn’t surprise you: it is 2, because differentiating with respect to b gives a, and a is 2.

Last, bump c. Then a·b isn’t affected at all, and c is simply added, so d rises by exactly the amount c was raised. The slope is 1 — the notebook prints 0.9999999999976694, the floating-point version of 1.

∂d/∂a = b = −3  ·  ∂d/∂b = a = 2  ·  ∂d/∂c = 1 at a = 2, b = −3, c = 10

This is where these notes leave the lecture. Its next step is the Value class: the object that wraps each number, remembers how it was made, and will compute all these derivatives without any nudging. That is part 2.

Beyond the lectureThe names. Each of these slopes is a partial derivative, written ∂d/∂a (“partial d by partial a”): the rate at which d changes when only a moves and every other input stays put. Collect one per input and you have the gradient, written ∇d: here ∇d = (∂d/∂a, ∂d/∂b, ∂d/∂c) = (b, a, 1) = (−3, 2, 1). As an arrow in the space of inputs it points the way d climbs fastest, and its opposite is the way d falls fastest.

Why it matters. Make d a loss and a, b, c weights, and the gradient says how to change every weight to make the loss smaller: move each one a little against its own slope, w ← w − α·∂L/∂w, where the small number α is the learning rate. Repeat, and you have gradient descent, which is how every network is trained (the lab’s “Step downhill” does one step with α = 0.01; move 15 trains a line this way). The method goes back to Augustin-Louis Cauchy in 1847 (Lemaréchal, “Cauchy and the gradient method”).

Why not just nudge? Nudging costs one extra pass through the expression for every input: fine for three, hopeless for a network with millions or billions of weights, where each training step would need millions of passes. Backpropagation gets every partial derivative from one forward pass and one backward pass, whatever the number of weights. That is the job of the Value class in part 2.

Watch forA derivative belongs to a point. ∂d/∂a = b = −3 only while b is −3: move b to +5 in the lab and the same nudge of a pushes d up. A gradient is always “at” some particular inputs, which is why training has to recompute it after every step.

Supervised learning

Chapter 1.1: inputs, outputs, and a model in between

Prince starts with the map. Artificial intelligence is the broad project of building systems that behave intelligently, by many means: logic, search, probabilistic reasoning. Machine learning is the part of AI that learns to make decisions by fitting mathematical models to observed data — and is now, the book notes, almost (wrongly) a synonym for AI. A deep neural network is one kind of machine-learning model, and fitting such models to data is deep learning. Machine learning divides roughly into three areas — supervised, unsupervised and reinforcement learning — and deep networks lead in all three. The book is deliberately neither very theoretical (no proofs) nor very practical (almost no code): its aim is the underlying ideas.

Supervised learning (section 1.1) means learning a mapping from an input to an output prediction. A real-world input — a sentence, a sound, a photo — is first encoded as a vector of numbers; the model maps that vector to another vector, which is translated back into a real-world prediction. For now, the model is a black box from numbers to numbers.

Regression and classification

  • Regression: the output is a continuous number — the monthly rent of a flat, from its floor area and number of rooms.
  • Multivariate regression: several numbers at once — a recipe’s cooking time and its calories.
  • Binary classification: one of two categories — is this product review positive or negative? The output is a probability for each.
  • Multiclass classification: one of N > 2 categories — which of N bird species is singing in this audio clip. The output is a vector of N probabilities.

Inputs

Inputs come in very different shapes. Tabular data is a fixed-length vector with no internal structure: shuffle the columns and build a new model, and the predictions should be the same. Text has variable length and its order matters — “the dog bit the postman” is not “the postman bit the dog” — so it is encoded as, for instance, the index of each word in a fixed vocabulary. Audio may be fixed in size but is huge: at the usual 44,100 samples a second, a three-second clip is 132,300 numbers. Images are huge too — a million-pixel colour photo is three million numbers — and have spatial structure: a pixel is closely related to the one just above it, even though the two sit far apart in the vector. A molecule has a varying number of atoms joined in varying ways, so the model must take in both the atoms and how they connect.

Models, training and supervision

So what is in the black box? Take a model that predicts a puppy’s weight from its age. The model is an equation describing how the average weight varies with age: put in an age, get out a weight. More precisely, it is a family of equations — a family of possible curves — and the particular one is chosen using training data, pairs of inputs and outputs. Training or fitting a model means searching that family for the equation that describes the training data most accurately. Because the labelled pairs act as a teacher, or supervisor, this is called supervised learning.

Deep neural networks are a particularly useful family: equations that can represent an extremely broad range of input–output relationships, and through which it is particularly easy to search. They can take inputs that are very large, of variable length and with internal structure, and return single numbers, several numbers, or probabilities over classes. Prince asks readers to suspend disbelief that such equations exist; chapters 3 and 4 build them.

Structured outputs

Outputs can be structured too: a label for every pixel (is it road or not?), a depth for every pixel, the words spoken in an audio clip, a French translation of an English sentence, or an image drawn from a caption. The last few are harder for two reasons. The answer can be genuinely ambiguous — there are many valid translations and many images that fit a caption — and the output has its own “grammar”: not every string of words is a sentence, and not every set of pixel values is a plausible picture. That grammar can be learned without any labels, from lots of examples, which leads to unsupervised learning.

Lecture ↔ bookThe lecture’s neural network took “the input data” and “the weights” as inputs (move 3). In the book’s language, the data is the input x, and the weights are the parameters that pick one equation out of the family.

No labels, or only rewards

Chapter 1.2–1.3: unsupervised and reinforcement learning

Unsupervised learning

Building a model from inputs with no output labels is unsupervised learning (section 1.2): with no labels there is no supervision, and the goal is to describe or understand the structure of the data rather than map inputs to outputs. The book concentrates on generative models, which learn to synthesise new examples that are statistically indistinguishable from the training data. Some describe the probability distribution of the data explicitly and generate by sampling from it; others just learn a way to produce new examples. They can also generate under constraints — conditional generation — such as filling in a missing part of a photo, or continuing a piece of text.

Text models are now so good that they can look intelligent: give one a document ending in a question and it will often “fill in” the answer as the likeliest continuation. But, the book argues, such a model knows only the statistics of language, not what its answers mean.

Many generative models rest on latent variables. Real data is far less varied than its raw size suggests: meaningful sentences are a tiny fraction of all strings of words, and real photos a tiny fraction of all possible pixel values, because they come from physical processes. So each example can be described by a few hidden, “latent”, numbers with a simple distribution chosen by design, and a deep network learns the mapping from those numbers to the data. Sample the latent numbers and run them through the network, and you get new examples. Find the latent numbers for two real examples and move smoothly between them, and you get plausible in-between examples.

Latent variables help supervised learning too, when outputs are structured. To make pictures from captions, learn a mapping between the latent variables behind text and those behind images. That needs fewer text–image pairs, since both sides are now small; it makes plausible pictures likelier; and adding randomness gives many different pictures that all fit the caption.

Reinforcement learning

The third area (section 1.3) brings in an agent that lives in a world and takes an action at each time step. Actions change the state of the world, not always predictably, and can produce rewards. The goal is to learn to choose actions that lead to high rewards on average. Two difficulties define the field:

  • Temporal credit assignment. A reward can arrive long after the action that earned it. A game character that finishes a level after four hundred jumps gets one reward at the end: which jumps mattered?
  • Exploration against exploitation. A delivery robot that has found a slow but safe route can keep using it (exploit what it knows) or try new streets that might be faster (explore).

Deep learning fits in, for example, as a policy network: a network that maps the observed state of the world to an action — sensor readings to wheel speeds, or a board position to a move.

Model, parameters, loss

Chapter 2.1: y = f[x, φ], and what “training” means

Chapter 2 makes chapter 1’s picture precise. A supervised model maps one or more inputs to one or more outputs — for example, a flat’s floor area and its distance from the station to its monthly rent. For now, inputs and outputs are vectors of a fixed size, always in the same order: structured or tabular data.

The model is just a mathematical function, an equation: pass the inputs through it and it computes the output. Computing a prediction this way is called inference.

y = f[x, φ]x the input · y the prediction · φ (“phi”) the parameters · the book writes functions with square brackets

The equation has a fixed form, but it also contains parameters, φ. Different parameter values give different outputs, so the equation describes a family of possible relationships between input and output, and the parameters pick out one member.

Training (or learning) a model means finding parameters that make sensible predictions. You have a training set of I pairs of inputs and outputs, {xi, yi}, and you want parameters that map each training input as closely as possible to its output. The mismatch is measured by the loss, L: a single number that sums up how badly the model predicts the training outputs. Since it depends on the parameters, write it L[φ], and training searches for the parameters that make it smallest:

φ̂ = argminφ L[φ]“φ-hat is the φ that minimises the loss”

If the loss is small after this search, the model predicts its training data well. Then you must check how well it does on test data it didn’t see during training — how well it generalises — and if that is good enough, the model is ready to use.

Fitting a line

Chapter 2.2: two parameters, a least-squares loss, and walking downhill

The book’s worked example (section 2.2) is the simplest model there is: 1D linear regression, one input x and one output y, related by a straight line.

y = f[x, φ] = φ0 + φ1xφ0 the y-intercept · φ1 the slope

It has two parameters, φ = [φ0, φ1]. Each pair of values gives a different line, so the equation defines the family of all lines, and the parameters choose one.

The loss

Which line is best for a set of training pairs? Some lines are obviously closer to the points than others, but you need a principled score. For each training pair, compare the model’s prediction f[xi, φ] — the height of the line at xi — with the true yi. Square each deviation and add them all up:

L[φ] = Σi (φ0 + φ1xi − yi)2the least-squares loss: smaller is a better fit

Because the best parameters minimise a sum of squares, this is a least-squares loss. Squaring makes the direction of a miss — above or below the line — irrelevant (chapter 5 gives deeper reasons for the choice). Seen as a function of the parameters, L[φ] is the loss function or cost function. With only two parameters you can compute it for every combination and look at it as a surface, or as a map seen from above; the best line sits at the lowest point.

Training

Finding the parameters that minimise the loss is called model fitting, training or learning. The basic method: start from random parameters and walk downhill. Measure the gradient of the surface where you are, take a step in the direction that goes most steeply down, and repeat until the ground is flat and nothing improves. For a line this isn’t actually necessary — a formula gives the best parameters directly — but the walking method works for models where no formula exists, and where there are far too many parameters to try every combination.

Testing and generalising

Chapter 2.2.4–2.3: underfitting, overfitting, and the road ahead

A trained model is meant for the real world, so you measure it by computing the loss on a separate set of test data (section 2.2.4). How well it does there depends partly on how representative and complete the training data was, and partly on how expressive the model is. Too simple a model — a line, for a relationship that curves — can’t capture the truth: that is underfitting. Too expressive a model can latch onto quirks of the particular training data and make strange predictions elsewhere: that is overfitting.

The chapter’s summary (section 2.3) is the whole plan of the book in four sentences. A supervised model is a function y = f[x, φ] whose particular relationship is set by its parameters φ. To train it, define a loss L[φ] over a training set that measures the mismatch between predictions and true outputs. Search for the parameters that minimise it. Then evaluate on different, test data to see how well it generalises.

Three hidden units

Chapter 3.1: lines, clipped at zero, weighted and added

A line can only draw straight relationships. Chapter 3’s shallow neural networks draw piecewise-linear ones, and are expressive enough to approximate arbitrarily complicated relationships between many inputs and many outputs. Section 3.1 builds the idea from one example: a network with a scalar input x, a scalar output y, and ten parameters.

y = φ0 + φ1a[θ10 + θ11x] + φ2a[θ20 + θ21x] + φ3a[θ30 + θ31x]

Read it in three steps. First, compute three linear functions of the input, θ10 + θ11x and so on. Second, pass each result through an activation function, a[·]. Third, weight the three results by φ1, φ2 and φ3, add them up, and add an offset φ0.

The commonest activation, and the one the book uses throughout, is the rectified linear unit, or ReLU: a[z] = ReLU[z] returns z when z is positive and 0 otherwise. It clips negative values to zero.

Why the result is piecewise linear

Split the calculation in two. The intermediate quantities h1 = a[θ10 + θ11x], h2 and h3 are the hidden units, and the output is a linear combination of them: y = φ0 + φ1h1 + φ2h2 + φ3h3.

Each hidden unit is a line in x, clipped by the ReLU wherever it goes below zero. The place where each line crosses zero becomes a joint in the final output. The three clipped lines are scaled by their φ weights and added, and φ0 sets the overall height. So the network describes a family of continuous piecewise-linear functions with up to four linear regions; the ten parameters set where the joints are, how steep each piece is, and how high the whole thing sits.

Each linear region has its own activation pattern. A unit that is clipped there is inactive; one that isn’t is active. Inside a region, the slope is the sum of θd1·φd over the active units only. Each unit contributes one joint, so three units give at most four regions — but only three of the four slopes are independent: the fourth is either zero (if every unit is inactive there) or a sum of the others.

Networks are usually drawn with the input on the left, the hidden units in the middle and the output on the right, each arrow standing for a parameter; the offsets are normally left out of the picture.

    Universal approximation

    Chapter 3.2: enough joints can draw any curve

    Section 3.2 generalises from three hidden units to D of them: unit d is hd = a[θd0 + θd1x], and the output is y = φ0 + Σd φdhd.

    The number of hidden units measures the network’s capacity. With ReLU activations, D units give at most D joints, so the output is piecewise linear with at most D + 1 linear regions. Add units, and the network can approximate more complicated functions.

    In fact, with enough hidden units, a shallow network can describe any continuous one-dimensional function on a closed, bounded interval to any precision you like. The reason: every new unit adds another linear region, and as the regions multiply, each covers a smaller stretch of the function, which a straight line approximates better and better. The universal approximation theorem proves the general version: for any continuous function there exists a shallow network that approximates it to any specified precision — and the same holds with many inputs and outputs.

    More inputs, more outputs

    Chapter 3.3–3.4: shared joints, tilted planes, and the general case

    Several outputs

    To predict several outputs (section 3.3.1), keep the same hidden units and give each output its own linear combination of them. With four hidden units and two outputs, y1 = φ10 + Σ φ1dhd and y2 = φ20 + Σ φ2dhd. Because the joints come from the hidden units, both outputs have their joints in exactly the same places; only their slopes and heights differ.

    Several inputs

    For several inputs (section 3.3.2), each hidden unit gets one slope per input: with two inputs, hd = a[θd0 + θd1x1 + θd2x2]. Each unit’s pre-activation is now a tilted plane over the (x1, x2) inputs. The ReLU clips it along a line, the clipped planes are weighted and added, and the result is a continuous surface made of flat convex polygons, each with its own activation pattern. With more than two inputs it can’t be drawn, but the idea is the same: the flat pieces become convex polytopes in the input space.

    The number of regions grows quickly with the number of inputs. Each unit’s joint is a hyperplane that separates where the unit is active from where it isn’t. With as many units as input dimensions, aligned with the axes, they would split two inputs into four quadrants, three into eight octants, and Di inputs into 2Di pieces. Real networks have more units than inputs, so they usually make many more. The book’s notes give the exact ceiling, from Thomas Zaslavsky (1975): D hyperplanes cut a Di-dimensional space into at most Σj=0…Di C(D, j) regions.     The jargon

    Chapter 3.5–3.6 and notes: layers, neurons, weights, biases — and where the words come from

    Section 3.5 admits that neural networks come with a lot of jargon, and lists it:

    • Layers. The inputs are the input layer, the hidden units the hidden layer, the outputs the output layer. Hidden units are also called neurons.
    • Pre-activations and activations. The values going into the hidden units, before the ReLU, are pre-activations; the values after it are activations.
    • Multi-layer perceptron (MLP). For historical reasons, any network with at least one hidden layer. One hidden layer makes it shallow; several make it deep.
    • Feed-forward. The connections form an acyclic graph: no loops, information flows one way.
    • Fully connected. Every unit in one layer connects to every unit in the next.
    • Weights and biases. The slope parameters on the connections are weights; the offsets are biases.

    The chapter’s summary (section 3.6): a shallow network computes several linear functions of the input, passes each through an activation function, and takes linear combinations of the results to form the outputs. It divides the input space into piecewise-linear regions, and with enough hidden units it can approximate any continuous function to any precision.

    From the chapter’s notes

    Why “neural”? The link to the brain is tenuous: diagrams of densely connected nodes look superficially like neurons, but there is scant evidence that brains compute this way, and the book finds biology unhelpful from here on. History: Warren McCulloch and Walter Pitts proposed an artificial neuron in 1943; Frank Rosenblatt’s perceptron of 1958 combined inputs linearly, thresholded them, and came with a learning rule; Marvin Minsky and Seymour Papert argued in 1969 that a single linear layer was too weak and that hidden layers would help, but that Rosenblatt’s rule couldn’t train them — and only in the 1980s did backpropagation give a practical way to do it.

    Activation functions. The ReLU goes back to Kunihiko Fukushima in 1969, but early networks mostly used the S-shaped logistic sigmoid and tanh. The ReLU was re-popularised around 2009–2011 and is part of why modern networks work. Its derivative is exactly 1 for every positive input, which keeps training stable, while sigmoids saturate — their slopes fade to almost zero for large positive or negative inputs. Its weakness is the mirror image: for negative inputs the derivative is 0, so a unit whose input is negative for every training example can never learn — the dying ReLU problem. Variants such as the leaky ReLU (a small slope for negative inputs) and smooth functions such as softplus, GELU and Swish try to fix it; no single activation is clearly best.

    Linear or affine? Strictly, a function with an added offset, like φ0 + φ1h1, is affine, not linear — doubling its inputs doesn’t double its output. Machine learning calls both “linear”, and so does the book.

    Folding

    Chapter 4.1: feed one network into another

    Chapter 4 adds layers. With ReLU activations, deep networks, like shallow ones, describe piecewise-linear functions, and shallow networks can already describe anything given enough units. The catch is that for some functions “enough” is impractically many. Deep networks produce far more linear regions for the same number of parameters, so in practice they can describe a broader family of functions.

    Section 4.1 gets the intuition by composing two shallow networks, each with three hidden units: the first takes x and returns y, and the second takes that y and returns y′. The result is still piecewise linear, but it can have more regions than a shallow network with six hidden units. Suppose the first network’s output zig-zags: three regions with slopes alternating up, down, up, each sweeping over the same range of y. Then three different stretches of x all map onto that range, and the second network’s function is applied three times over — copied, flipped and rescaled according to the slopes of the first. Its three regions become nine.

    Another way to see it: the first network folds the input space back on top of itself, so that several inputs produce the same output. The second network then draws its function on the folded space, and the drawing is replicated at every point that was folded on top of another. The same happens with more inputs: in the book’s two-input example, a first network with seven regions feeding a second with two produces thirteen.

The second ReLU clips each of those, adding new joints. And the output is a linear combination of the clipped functions. So you can think of each layer as folding the input, or as creating new functions that are clipped (making new regions) and recombined. The first weight matrix Ω0 is D1 × Di, the last, ΩK, is Do × DK, and each one in between, Ωk, is Dk+1 × Dk: rows for the layer it feeds, columns for the layer it reads. The whole network fits in one nested line: y = βK + ΩKa[βK−1 + ΩK−1a[… a[β0 + Ω0x] …]].

    Shallow versus deep

    Chapter 4.5–4.6: why depth wins in practice

    Section 4.5 compares the two kinds of network on five counts.

    • Approximating functions (4.5.1). Both can approximate any continuous function. A deep network can always copy a shallow one — make its second network the identity — so the universal approximation theorem carries over.
    • Regions per parameter (4.5.2). With one input and one output, a shallow network with D > 2 units makes at most D + 1 regions from 3D + 1 parameters. A deep network with K layers of D units makes up to (D + 1)K regions from 3D + 1 + (K − 1)D(D + 1) parameters. For a fixed budget, depth produces vastly more complex functions, and the gap grows with more inputs. But those regions aren’t independent: the folds give them dependencies and symmetries, so the extra regions help only if the real-world function has similar structure, or really is a composition of simpler functions.
    • Depth efficiency (4.5.3). Some functions need a shallow network with exponentially more hidden units to match a deep one. Attractive — but it isn’t clear that the functions we care about in practice are of that kind.
    • Large, structured inputs (4.5.4). For an image of a million pixels, a fully connected network would need a prohibitive number of parameters, and would have to learn to recognise the same object separately at every position. The fix is to process small patches in parallel and integrate them over larger and larger regions — local to global, which needs several layers (chapter 10, convolutional networks).
    • Training and generalisation (4.5.5). Moderately deep networks are usually easier to train than shallow ones, perhaps because large over-parameterised models have many roughly equivalent good solutions to find; very deep ones get harder again (chapter 11). Deep networks also seem to generalise better, and the best results on most tasks use tens or hundreds of layers. Neither fact is well understood (chapter 20).
    Try it — regions per parameter

    One input, one output, K hidden layers of D units. The deep network’s ceiling is (D + 1)K regions; the shallow network gets exactly the same parameter budget, all in one layer. The book’s own example is D = 10, K = 5.

    parameters deep: up to shallow, same budget: up to

    The chapter’s summary (section 4.6) gathers it up: composing two shallow networks folds the input and replicates the second network’s function; that composition is a special case of a two-layer deep network, whose ReLUs clip their input functions in many places; width and depth are hyperparameters; and deep networks win in practice because they make far more regions per parameter, handle some functions exponentially more efficiently, process large structured inputs in stages, and give the best results.

    From the notes: the term “deep learning” was first used by Rina Dechter in 1986, but deep networks were hard to train well, and the modern era began with the leap in image classification by Krizhevsky and colleagues in 2012 — thanks, the book suggests, to bigger datasets, more computing power, the ReLU and stochastic gradient descent. There is also a depth version of the universal approximation theorem: given enough layers, ReLU networks only Di + 4 units wide can approximate any suitable function (Lu and colleagues, 2017).

    Beyond the bookThe depth-efficiency results in the notes are worth knowing by name. Telgarsky (2016, linked in move 21) built one-input functions that a narrow network with O(k3) layers computes, but that no network with only O(k) layers can match without about 2k units per layer; Ronen Eldan and Ohad Shamir showed that with many inputs even three layers can beat two (“The power of depth for feedforward neural networks”, 2016).

    1. What does g.backward() compute in micrograd?

    The forward pass computes g; the backward pass fills in ∂g/∂(node) for every node, inputs included (move 2).

    2. a.grad is 138. What does that mean?

    A derivative is a sensitivity: the response per unit of nudge, for tiny nudges. It is positive here, so g rises.

    3. Why does micrograd work with single numbers instead of tensors?

    “None of the math changes”: tensors are arrays of scalars, processed in parallel for efficiency (move 4).

    4. What is the slope of f(x) = 3x² − 4x + 5 at x = −3?

    6x − 4 = −18 − 4 = −22. 44 is f(−3) itself, the height; 14 is the slope at +3.

    5. Where is that slope zero?

    6x − 4 = 0 at x = 2/3, the bottom of the parabola, where a nudge leaves f almost unchanged.

    6. At x = 3 with h = 10−16, the code prints a slope of 0.0. Why?

    Neighbouring floats near 3 are about 4.4 × 10−16 apart, so a nudge of 10−16 disappears in rounding (move 7).

    7. With h = 0.001 the estimate at x = 3 is 14.003. The extra 0.003 is…

    For this parabola the forward difference is too big by exactly 3h. Rounding only matters for far smaller h.

    8. d = a·b + c at a = 2, b = −3, c = 10. What is ∂d/∂a?

    Differentiating a·b + c with respect to a gives b, which is −3: raising a makes d smaller.

    9. And ∂d/∂c?

    c is simply added, so d rises by exactly as much as c does.

    10. In the book’s y = f[x, φ], what is φ?

    φ picks one member of the model’s family of functions; training searches for the φ that minimises L[φ] (move 14).

    11. The least-squares loss for a line…

    L[φ] = Σ(φ0 + φ1xi − yi)2. Squaring makes misses above and below count the same.

    12. A model with zero training loss and a large test loss is…

    It has fitted the training data’s quirks, like the degree-9 curve in move 16.

    13. A shallow ReLU network with one input and D hidden units has at most how many linear regions?

    Each unit adds one joint, and D joints cut the line into D + 1 pieces (move 18).

    14. With no nonlinear activation, what can a network with ten hidden layers represent?

    A linear function of a linear function is linear, so every layer collapses into one (move 19).

    15. Why can deep networks make far more regions than shallow ones with the same parameters?

    Composition multiplies regions instead of adding them: 3 × 3 = 9 in the book’s example, 2K in the tent lab (move 21).

    16. Ω1 takes layer 1 (8 units) to layer 2 (6 units). What size is it?

    Rows for the layer it feeds, columns for the layer it reads: Dk+1 × Dk (move 23).

    17. “The reward comes long after the action that earned it” is the problem of…
